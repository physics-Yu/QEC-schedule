# 单台大容量 rigid AOD 的联合运输

`MultiTrapGreedyCompiler` 的物理容量检查从固定 1×2/1×4 改为 1×N（N≥2）。固定列间距仍为 10 μm；容量上限由输入接口限制。所有列共享同一刚性平移，实际开启列由交接 bindings 决定，不是 N 台独立 AOD。

## 通用整行工具

```python
compiler.transfer_group(builder, {atom_id: destination_slm_id}, label="Row staging")
```

该工具要求空载 AOD、真实 SLM 起点、同排且对齐于 AOD 列间距的原子组，以及保持同一平移向量的目标位置。它构造真实关灯定位、联合 LOAD、经过全阵列审计的 A* 运输、联合 OFFLOAD。来源不必占满所有容量列；所有启用交点均有明确 bindings。非刚性目标、超容量、目标已占据、捕获/路径/支撑不合法均由原验证器拒绝。

## M4 候选与终态优化

联合预置需求集合取自所有尚未完成 CZ 的操作数，允许提前移动 blocked 门的原子，但不改变门的 READY 条件或提前提交效果。每个当前操作数所在物理行，选择包含该操作数、可容纳最多需求原子的一个 AOD 宽度窗口；不枚举原子子集，也不识别特定编码、电路名字或 GHZ 模式。

当前 CZ 的两个操作数不必来自同一行：可以联合预置其中一侧与其他未来所需原子，然后由正常门编译服务执行当前 CZ。候选仍按真实准备加门服务成本比较，不为用满容量强行搬运。

显式终态清理按来源行及相同目标平移向量组成联合归还组，每个容量窗口至多尝试一次。已有单活动 cell 先归还；不能联合完成的分组继续使用原逐颗目标构造。所有试探都在私有 builder 中完成，失败不会部分修改实时状态。

## 已验证边界

`tests/test_large_aod.py` 使用 1×9 和 1×36 的真实全行装卸、运输、完整归还及满载 checkpoint 恢复；一次预置加一次归还合计两次 LOAD、两次 OFFLOAD。另覆盖未来 blocked 操作数、跨行 CZ 的单侧预置、非刚性目标和占据目标拒绝。

该扩展仍由 cell 0 执行逐个 CZ 服务；没有实现多 cell 跨门驻留或一个 pulse 的批量 CZ。联合运输不会放宽四邻格预留、碰撞、5 μm 单比特寻址条件、实际/期望作用对一致性或完整容量边界。允许编辑大电路不等于保证任意大输入在给定编译预算内成功。

## 大容量校验成本

`AODRuntimeState` 在每个不可变实例内保存已经验证的派生 axes；新 pose、形状或容量仍重新构造并验证。缓存不是 dataclass 字段，不进入 checkpoint，保留整数、浮点数和 signed zero 的原序列化表示；行列开关及 holder 支撑始终独立验证。

EZ 四邻格验证缓存的只有不可变 world/zone/grid 几何。每次仍从当前 DAG、holder 和 alive 状态计算伙伴许可；以 x 坐标范围筛选可能接近保留点的原子，再执行原精确 Euclidean 容差检查。多个冲突仍按原 holder 顺序、原四点顺序报告第一个错误。`tests/test_geometry_derivation_cache.py` 用独立全扫描 oracle 覆盖容差边界、重复热查询、伙伴切换/最后 CZ 完成、容量和非均匀 axes，以及数值序列化。
