# 二维 surface-code patch 与并行横向门的调研和实现建议

调研日期：2026-09-12。本轮用户要求把四个码块真正排成二维 patch，并实现相容门的并行；上一轮 36 原子物理单行布局不满足这一展示和调度目标。本文是源码之外的研究及构造建议，实际可执行性仍以新的物理编译、独立重放与量子核验为准。

## 2. 具体二维布局

令每块局部编号 `q=3r+c`，`r,c∈{0,1,2}`，全局原子为 `Q(9b+q)`（三位补零）。取 patch 内间距10 μm、相邻patch原点间距40 μm。以下为可直接生成的**建议坐标**，均为工程选择，不是论文设备坐标的抄录。

| 块 | SZ原点(μm) | 数据原子 |
| --- | --- | --- |
| L0 | (10,−90) | Q000–Q008 |
| L1 | (50,−90) | Q009–Q017 |
| L2 | (10,−50) | Q018–Q026 |
| L3 | (50,−50) | Q027–Q035 |

局部坐标公式为 `position(b,r,c)=origin(b)+(10c,10r)`。因此每块都是可见的3×3数据patch，四块整体是2×2排列；相邻块最近数据间距20 μm。

```text
SZ                         EZ：两个3×3静态处理位
L0: 0 1 2    L1: 0 1 2     bay A：origin (10,10)
    3 4 5        3 4 5     bay B：origin (50,10)
    6 7 8        6 7 8

L2: 0 1 2    L3: 0 1 2
    3 4 5        3 4 5
    6 7 8        6 7 8
```

EZ只需同时容纳两组静态anchor patch及其近接伙伴，数据门位点横向约62 μm、纵向20 μm。建议SZ容纳y=−90..−30，EZ含y=10..30及必要运动余量，world还需包含整个AOD容量和回程。可以对所有坐标整体平移来适配现有正坐标world，物理间距与对应关系不变。

这是紧凑的双处理位方案。另一可行工程选择是把四个patch在SZ的2×2形状全部整体搬入较大EZ；但不能将更大的全区照明范围默认归于同一台实验设备。2024论文Methods “Zone parameter choices”给出35 μm均匀高度；2026论文Methods “Experimental layout”给出60 μm均匀高度。这些值随设备不同，不是普适EZ尺寸。

## 3. 两层真正并行的逻辑互连

量子目标沿用先编码 `L0=|+>_L`、`L1,L2,L3=|0>_L`，再执行逻辑CNOT `0→1`，然后 `0→2` 与 `1→3`。三个逻辑CNOT的物理门数仍为27，后两者作用于不相交的块，可共同组成第二层。

### 第一层：9个对应数据对

将L0放在EZ bay A。L1的每个目标数据原子近接到L0对应位置：

```text
L0(q) = (10+10c, 10+10r)
L1(q) = L0(q) + (2,0)
intended = {(Q[q],Q[9+q]) : q=0..8}
```

一次共同CZ脉冲同时执行9个物理CZ。此处“transversal”描述**对应物理门的结构**；完整逻辑门仍须为 `H(targets) → CZ(all pairs) → H(targets)`，不能把同朝向surface patches之间的裸物理CZ层直接称为logical CZ。

### 第二层：18个对应数据对

第一层之后把L0、L1恢复在EZ bay A/B的10 μm稀疏patch。把仍在SZ下排的L2/L3一起提取、运输，分别交错到L0/L1旁：

```text
L2(q) = L0(q) + (2,0)
L3(q) = L1(q) + (2,0)
intended = {(Q[q],Q[18+q]), (Q[9+q],Q[27+q]) : q=0..8}
```

一次共同CZ脉冲执行18个物理CZ。独立枚举上述建议端点的全部36原子对，第一层实际距离≤2 μm的EZ对恰好9组，第二层恰好18组；两层的最近非目标原子对距离均为8 μm。此计算只证明指定端点的配对几何，不证明运输路径或真实Rydberg串扰。

**单比特前后H必须在分离态执行**：现行规则要求目标与其他原子距离≥5 μm。在2 μm交错态，不能立即执行后H。顺序应为分离态前H、装载/运输/近接、并行CZ、撤离到合法分离态、后H。可卸回10 μm SLM patch后打光；若停在AOD上则需证明所有邻距、稳定支撑和区域寻址均合法。前H/后H是物理CNOT分解，不要求把它们单独解释成码空间中的logical H。

## 4. 单台AOD怎样实现块移动

**矩形Cartesian阵列不要求等间距。** [Bluvstein等2022论文](https://arxiv.org/html/2112.03923v1) Methods “Optical tweezer generation” 中，多路RF频率分别定义各x列和y行的位置，可分别随时间调节；其实际运输协议保持行列顺序，执行平移、伸缩，不让轴相交。这支持有序非均匀轴，不能把本项目旧rigid后端的等间距限制当成实验物理限制。

四patch布局优先直接表示为：

```text
x_offsets = (0,10,20,40,50,60)
y_offsets = (0,10,20,40,50,60)
capacity = 6 × 6 = 36
```

所有行列开启恰好是四个3×3 patch的36个交点，无须在30 μm处添加任何轴。抓隔开的列或行可以直接配置这些非均匀坐标，或只打开所需的有序轴子集；活动交点仍必须完整计算为 `X_enabled × Y_enabled`。**36数据原子的这次布局不要求49trap容量。**

固定上述非均匀轴，然后令所有x坐标加同一个`dx`、所有y坐标加同一个`dy`，相对几何完全不变，仍是刚性平移。动态改变各个轴之间的距离才是额外的重构能力；无需为支持初始非均匀数组就自动宣称已经支持所有伸缩路径。

rigid阵列也可以搬整个3×3块，无须把9个trap改成独立运动。两块水平并排时，所需移动点是三行与六列的Cartesian积：

```text
x_offsets = (0,10,20,40,50,60)
y_offsets = (0,10,20)
capacity = 3 × 6 = 18
```

若要兼容此前均匀格点实现，也可以用以下稀疏mask表达相同活动坐标：

```text
active rows = {0,1,2}
active columns = {0,1,2,4,5,6}
spacing = 10 μm
```

这里3×7容量、列3关闭，或四块时7×7容量、行列都启用 `{0,1,2,4,5,6}`，只是均匀轴加空轴的兼容表示。与非均匀3×6/6×6相比，映射到对应的活动交点后，固定平移的真实trap轨迹可以相同；它们的完整硬件配置空间不同，因为6轴方案没有中间第7根可重新启用的轴。inactive行列坐标仍需在world bounds内，不得借关灯跳过容量边界。

动态重构时须保持cell的row/column身份：`x_0(t)<x_1(t)<...`、`y_0(t)<y_1(t)<...`，并满足最小轴距。不能把从左到右的列顺序反转后重新编号，不能通过关灯让载原子瞬移，也不能认为同列各原子可独立横移。共用线性或三次插值下，有序且满足间距的端点可给出轴间距全程下界；仍必须检查与静止原子、SLM、其他移动原子的整段轨迹。实际RF带宽、功率均匀性、频率互调及加热需单独标定，本文没有从坐标可表示推导真机无限容量。

当前源码审阅（2026-09-12，修改前）：`domain/aod.py:AODConfiguration` 已表示任意有序x/y轴；但 `hardware/rigid_aod.py:target_aod` 拒绝offset数组，`capture_closure`仍用除spacing/round计算cell。这些是待修的实现限制。支持固定非均匀轴时，捕获应依据实际活动交点坐标匹配，并跳过远离所有活动trap的间隔SLM原子，不能把整个包围矩形当连续光阱。移动可保持offset不变只更新pose；在本轮固定轴策略中拒绝额外变形，与row_column的动态变距分开验收。

每次选择活动行列都必须先计算完整Cartesian闭包。选三个patch或三个不成矩形的数据子集可能产生第四处活动trap，那里若有SLM原子就涉及附带捕获/碰撞，不能忽略。对于编码阶段的内部CZ，可按READY匹配对及共同刚性位移分组，再审核闭包；无法共同运输的组合拆批。至少跨两个或四个patch中同几何的编码门有批处理机会，但不能从四块数目直接保证每一步四门并行。

建议保留正交通道和显式提取动作：先LOAD，沿短正交段移出绑定SLM，再进入半格通道，整体搬运，最后近接。不能从一块patch横穿另一块的已占据整行再声称端点安全。对规则网格可先错开y至`2.5+5k`通道后横移，再沿垂直接近；整个二维活动阵列、开启空trap、所有附带原子和每一段仍由后端验证。移动途中不打CZ；相距2 μm不是自动执行门。

## 5. 四近邻禁占与其他硬规则

用户本轮授权必要时关闭“为下一CZ保留四近邻格点”的附加调度规则。这不是关闭碰撞校验。对于world网格5 μm而patch pitch10 μm的完整稀疏patch，静态相邻数据原子并不占据四邻5 μm格点；上述2 μm CZ端点也不在5 μm格点上，因而**不一定需要关闭这条规则**。

若内部编码或暂存方案确实受其限制，可在此次二维实验的显式硬件配置中关闭并记录原因；仍保持最小物理距离、开启空trap扫掠、holder支撑、row/column闭包、作用区、1Q≥5 μm及actual/intended pair检查。不可为了批量门通过而扩大2 μm作用距离或忽略旁观配对。

## 6. 可编辑线路与验收应保留什么

- 初态真的符合四个3×3物理patch，而非仅修改标签；SZ/EZ交接后完整恢复二维终态。
- 输入仍是逐个H/CZ门。批处理器从READY CZ匹配及可实现几何生成批次，不要求输入只能是这个GHZ模板。用户改门后重新编译，冲突拆批或明确失败。
- 后端每个pulse统一核验全部存活EZ原子的真实近接对集合，必须与该批所有预期CZ对集合完全相等，且每个qubit最多出现一次。
- 一个批脉冲拥有一个实际持续区间和完整目标集合，原子资源、全局光照资源、gate DAG和结果都原子提交。不能把9条独立顺序pulse在动画里改成同色来冒充并行。
- 两种策略使用完全相同的二维初态、硬件、门集与完整终态；分别报告总CZ门数、真实pulse批次数、最大每批CZ数、并行1Q数、移动距离和总模拟时间。
- 独立物理重放验证无碰撞/旁观pair；实际完成门顺序再次验证36个有符号GHZ目标稳定子。量子通过与路径通过分别报告。

本轮明确要实现并行2Q，因此需要真正开放此前列在M5中的最小批量CZ合同；不能以旧M4单pair范围把用户要求自动缩回逐CZ，也不能把受限批量能力说成全部M5完成。可先验收9对，再验收18对；如果第二阶段在单台rigid阵列下的真实路径尚未通过，报告9对可执行与18对未完成的具体差异，不用示意坐标替代执行证据。
