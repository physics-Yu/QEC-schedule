# SMT 联合批次实验：结果、边界与下一步

2026-09-14。已完成小规模对照、真实物理执行、独立重放及交互验收。入口：<http://127.0.0.1:8793/>。

## 结论

联合求解确实找到现有分组启发式遗漏的合法并行组合；多阶段有时比“本轮门数最多”更省总时间。但 SMT 并没有普遍降低编译耗时，且本实验没有证明物理总时长最优。

这支持优先建立可替换的联合约束规划器，并保留轻量贪心；不支持将所有电路无条件切换为全局 SMT 或宣称已完成 OLSQ-DPQA 复现。

## 实验合同与公平性

- 四个固定输入；三个策略每次由**独立 Python 进程**运行，同一个输入生成的完整初始 checkpoint SHA256 必须一致。共两轮、24 次正式运行，全部完成、门效果恰好一次、终态验证与重放 checkpoint 逐字一致。
- 布局：全部原子初始在 EZ 的实际 SLM trap，原子格点相隔 10 μm；同一台 regular rigid AOD。没有免费从 SZ 搬入 EZ，也没有可优化的初始布局。每批后回到原 SLM，末尾恢复原 AOD 坐标、SLM 和行列开关。
- 共同保持原物理规则，包括 EZ 四邻停驻保护、完整阵列边界、全部活动空交点扫掠、支撑及交接、原子碰撞、真实 CZ 作用对。同型 1Q 可并行且每次 1 μs，异型不重叠。
- 共同动作族：同批移动原子有相同位移；每个移动原子必须参加本批 CZ。允许活动交点为空，但不允许未经声明的旁观原子被附带捕获。选门、移动侧、四个方向的 2 μm 作用位置、捕获闭包、容量由 SMT 联合决定；捕获原点取所选原子的最小 x/y，与原有 regular-grid realizer 一致。
- 暂不包含任意 EZ 重分配、跨批驻留、动态行列伸缩、非均匀轴、跨批资源重叠、测量/reset/反馈或绕开旁观者而额外搬运它们。支持这些功能的其他环境/实验代码未被删除。
- 原始基线来自 `patch_greedy.candidate_groups/preflight_group/batch_service`，保留原有按实际服务耗时/门数评分和下界剪枝。适配到共同 EZ 起点与终态，并使用共同单比特阶段边界；不是未改动的整段 `run_patch`，也不是单 trap M4。实验比较的是该公共动作族中的批次策略。
- 三策略每次总规划预算 60s，路由展开 20000；SMT 每次 check 5000ms、最多 24 个模型提案。上层另有总预算+30s 的进程硬截止，包含不可及时中断的构造、执行或输出。

## 为什么获益，以及为什么有时不获益

### 矩形闭包

14 原子中有 6 个待做 CZ，另 2 个旁观原子。选全部候选操作数时，活动行×列会捕获旁观者。旧启发式尝试最大分组、同源行/列子组与单原子回退，却不遍历所有多行多列子集。

SMT 单步选出了合法 5 门组合；独立穷举 oracle 验证，在声明的 endpoint 动作族内最大批次确实为 5。多阶段求出了 2 批完成方案；独立子集覆盖枚举也给出最少 2 批。

更大的第一批不等于更快的全过程：5+1 与 2+4 都有两次 CZ，但后者的后续捕获位置和空 AOD 重定位更便宜。相对贪心，多阶段总物理时间下降 **36.0%**。

三种方案中原子累计路程均为 516μm，均为 6 次原子 LOAD 和 6 次原子 OFFLOAD。区别在于把这些原子放进几个共同的运输/交接时间区间，以及空载重定位。不能把原子次减少当成加速原因。

| 逐原子汇总 | 贪心 | SMT 单步 | SMT 多阶段 |
|---|---:|---:|---:|
| 总原子路程 / μm | 516 | 516 | 516 |
| LOAD / OFFLOAD 原子次 | 6 / 6 | 6 / 6 | 6 / 6 |
| LOAD / OFFLOAD 操作批次 | 3 / 3 | 2 / 2 | 2 / 2 |
| AOD 累计移动 / μm | 383 | 292 | 237 |
| 累计原子等待 / atom·μs | 16901.0 | 11548.8 | 10008.8 |

等待为逐原子统计的累计值，不是整机时长；旁观原子也计入。每个运行目录提供每原子的 CSV/JSON。

### 交叉依赖

单步最大门数没有改善现有贪心的五批结果。多阶段保留了最后四门的合批机会，用四批完成；正式物理时间改善 **15.9%**，复测改善 **16.6%**。但多阶段编译执行耗时约为正式贪心的 2.57 倍。

### 简单并行与混合门

原贪心已找到同样的物理调度结果，SMT 增加的成本没有产生排程收益。因此应保留快速路径，在值得联合搜索时才使用更强求解器。

## 编译耗时具体花在哪里

交叉依赖、多阶段（attempt2）：模型构造 **1.605s**，Z3 求解 **0.586s**，物理程序实现 **0.619s**，实际执行/审计/记录 **2.100s**；其余为编排开销。不是 HTML 渲染导致慢，也不全是 SMT 求解本身。

当前每个 horizon 重建约束；离散位移种类 D≤8G，每阶段为原子对建立 endpoint 表，量级约 O(S·D·N²)，增大 horizon 会重复前面结构。这是明确的下一步优化目标，而不是盲目提高超时。

建议顺序：

1. 缓存与版本绑定的静态几何/位移事实，复用 horizon 的公共约束；用逻辑依赖深度和门类型得到安全的阶段数下界，跳过显然不可能的 horizon。
2. 保留贪心 incumbent；仅在其批次受闭包限制、或短窗口的后续合批机会明显时求 SMT，记录相同预算下的增益。
3. 保留少量不同资源/终态的并列解，以真实路由费用重排；必要时加入多阶段时间成本，不能将本轮代理最优升级为物理最优。
4. 再扩展跨批驻留、辅助腾挪与更多 EZ 落点。它们需要新的状态转移变量及实际可实现的交接合同；不由这次测试自动证明支持。

## 失败反馈与核验

- 模型区分 SAT、UNSAT、UNKNOWN。UNSAT 只针对本轮有限 endpoint 模型；UNKNOWN（超时/预算）不等于无解。
- 外部完整物理构造失败，保留 model、违规码及信息，继续有限搜索；排除的是这次赋值，未把路由预算耗尽写成物理禁止。
- 真实 UI 负控：将 SMT 单次预算设为 1ms，单步与多阶段均返回 UNKNOWN，弹窗显示未完整通过；贪心仍有真实结果。无效 AOD 行数也会明确拒绝，不产生伪动画。
- 单元测试强制路由预算失败，确认 live 状态零提交、诊断和模型预算出口正常；这是注入测试，未冒充物理实验自然失败。
- 主实验未发现 SMT 的实际路线失败；贪心闭包案例有 16 条正常候选拒绝。没有因此修改碰撞或四邻条件。
- 相关 64 项 Python 测试通过，另 7 项 viewer/SLM 显示回归通过。非全仓回归。
- 浏览器为 Playwright 启动的真实 Edge headless；内置 CUA 连接不可用。最终 26 项检查通过，包括添加 X 并真实重编译、三个动画完整 32x 播放、终点、真实 EZ 区域标签、720px 响应布局、失败弹窗与无自动编译；无脚本错误。
- 新单 EZ 场景发现原 viewer 首区固定标成 STORAGE 的显示缺陷，已按真实 `zone_type` 修正并重导出动画。物理数据未改。
