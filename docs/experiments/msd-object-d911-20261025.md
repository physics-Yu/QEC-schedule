## Input recovery and model boundary

The existing 16-protocol d9/d11 component production was found in the independent
`C:/Users/yuyqp/.codex/worktrees/msd-experiment-standard/NADiT` checkout, under
`modules/physical_compiler/artifacts/surface-d9-d11-components-20261024/`.
The report's relative artifact path was absent in the main checkout, but the
complete templates and probability caches were retained in that worktree.
No source changes, old campaign implementation or unfinished server jobs were
imported. Generic code definitions and the existing factory recipe already
support these distances; new physical provider code was unnecessary for this path.

The explicit [migration tool](../../experiments/msd/extract_d9_d11_objects.py)
reads saved JSON only. It checks template content/source hashes, manifest and
protocol-stage references, timing conventions, noise identity and AOD Load/Store
boundaries. Each saved parallel step becomes a numeric component phase; no
AtomProgram is constructed, circuit expanded, compiler called or probability
estimator run. The tool is never imported or invoked by the runtime estimator.
Missing records fail rather than triggering a build or duration extrapolation.

Each catalog contains ten semantic objects: seven recorded base operations,
initialize-plus correction, three-round d3 raw injection, and accepted-only
growth/correction. The saved d9/d11 component exports provide the actual fold S+SE,
CNOT and ordinary target SE. Unused H and other catalog entries are not migrated.
The existing signed CNOT displacement and readout-height binding model applies;
layout/N/seed changes do not reconstruct component internals.

## Local paired acceptance

Both policies ran N=1/2, seeds=0/1 and two attempted production rounds per factory
in the existing vertical layout: eight pairs / sixteen real-factory cases.
The shared one-AOD scheduler, homogeneous component waves, corrected round join,
ideal external sink and original input Z error 0.01 are unchanged.

N=2 makespans in milliseconds:

| d | Seed | Accepted outputs / attempts | Async | Sync v2 |

| 11 | 0 | 4 / 4 | 1922.429945 | 1398.181972 |
| 11 | 1 | 3 / 4 | 1731.747209 | 1421.933825 |

N=1 is an exact async/sync timing control: d9 645.713685 / 631.706808 ms and
d11 789.356393 / 872.975948 ms for seeds 0/1, with two accepted outputs per run.
Each pair preserves all probability outcomes and invocation counts. Across
distances, identical seed numbers need not produce identical paths because the
raw port identity contains the distance. The larger-distance cached acceptance
also uses a different estimator method from the existing d3/d5/d7 references.

These are finite batches, not steady-state throughput or matched decoded-quality
results. Downstream injection/transport remain excluded by the ideal sink.
N4 layout comparisons and server scans were not run for d9/d11.

- Focused baseline: 33 fast passed, 7.67 s. New d9/d11 tests first failed on the
  unsupported-distance guard; the former uncovered-distance test now uses d13.
- Focused verification: 44 fast passed, 8.25 s. Tests cover full recipe objects,
  actual S costs, accepted-only growth, exact-evidence tampering, saved-template
  hash/mixed-step rejection and unchanged d3/d5/d7 catalog fingerprints.
- Mapped related verification: **121 fast passed**, 16.45 s pytest / 17.195 s
  bounded process time. No slow, bench or blanket repository suite ran.
- Ruff formatting/lint passed for four changed/new Python files; scoped strict
  mypy passed for the loader and offline converter with existing configuration.
- Re-extraction to a new directory reproduced both packaged catalogs byte for
  byte, including protocol-stage hashes. Original templates were only read.
- Independent readback of all sixteen cases verified **794 paired event records
  and 2826 paired invocation IDs**, one AOD with no overlapping modeled resource
  intervals, homogeneous waves, growth only on accepted raw events, and the
  rejection-inclusive next-round synchronization rule.
- All sixteen complete HTML schedules include the saved stage traces and actual
  block footprints; counts and per-factory time sums match their JSON inputs.
  The shared JavaScript passes Node syntax checking; 19 HTML links, 66 document
  links and all four paired configurations validate.
  No atomic route validation or browser screenshot is claimed.

Each worker loads ten component objects once. Both policies retain equal reuse:
d9 4461 lookups / 4431 hits / 30 numeric bindings; d11 4497 / 4467 / 30.
Template identities remain stable and physical compile, atom binding/expansion
and atom-construction counters are zero. Worker times are d9 async/sync
5.811/5.759 seconds and d11 7.097/6.896 seconds; total worker work is 25.563 s,
end-to-end launch time including startup/imports 34.600 s. Rendering is separate.
No case timed out; limits remain 20 s/case, 5 s/wave and 60 s/worker, with failure
stopping subsequent cases. No budget increase or automatic retry was used.

## Reproduce and inspect

Normal estimation only needs the packaged numeric files; it does not require
the old checkout or migration tool. Use a fresh output directory:

```powershell
$msdPython = 'C:\Users\yuyqp\Documents\ChatGPT\NADiT\modules\physical_compiler\.venv\Scripts\python.exe'
$env:PYTHONPATH = "$PWD;$PWD\modules\physical_compiler\src"
& $msdPython -m modules.logical_compiler.examples.factory_objects `
  --config experiments/msd/factory-objects-sync-d11.json `
  --output artifacts/msd-object-local/d11-sync-reproduction
if ($LASTEXITCODE -ne 0) { throw 'Run failed; stop before later work' }
& $msdPython -m modules.logical_compiler.examples.factory_schedule `
  --case artifacts/msd-object-local/d11-sync-reproduction/d11-n2-seed1.json `
  --output artifacts/msd-object-local/d11-sync-reproduction/complete-schedule.html
```

For explicit migration reproducibility only, run the JSON-only converter with
`--source <saved surface-d9-d11-components-20261024 directory>` and
`--output <fresh directory>`. It never attempts to rebuild missing inputs.
