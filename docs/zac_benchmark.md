# ZAC 大实例 CZ benchmark

2026-09-22 已新增[作者SA初始布局 × reuse四组实验](zac_initial_placement.md)，包含实际初态、共同绝对终态、四组回放与正负结果。本文下方原批次仍为固定初态对照，数据未覆盖。

入口是 `examples/benchmark_zac_reuse.py`。所有 case 使用未修改的作者前端，再交给本地运输、Executor、VisualRecorder 和共用 viewer。原小实例工作台保留，汇总页入口挂在“已生成实验”下面。

## 实验合同

- 默认规模 16、32、64、128 原子，8 个全匹配层，即 64、128、256、512 个物理 CZ。每层每颗原子恰好参与一次，ASAP 深度独立核对为 8。
- 三种合成线路：`repeat` 重复同一配对，作为复用正对照；`butterfly` 在异或位掩码 1、2、4…之间换伙伴；`random` 用 Python `random.Random(seed)` 每层随机完美匹配。默认 seed=20260921，可提供多个 seed。
- 重复 CZ 不消去；没有混入 1Q、QASM 重综合或初态优化。这不是作者完整应用 benchmark 或原硬件参数下的 AE 数值复现。
- 每个 case 的 reuse 开／关保持同一完整 CZ 输入、SZ 初始 holder、硬件几何、AOD 能力及完整终态。末尾必须恢复初始 holder、SLM masks、AOD axes/masks；失败前缀不得进入加速比。
- AOD 为 `2 × max(4, ceil(N/2))`，最大 128 交点。存储区与 EZ 容量随 N 增长；不同 N 的结果不能解释为固定硬件上的强扩展。相同深度的重复配对能并行搬运更多原子，因此物理完成时间可能相同，但主机执行成本仍随 N 增长。
- 世界边界、1 μm clearance、严格大于 1.01 μm 的轴间距、2 μm CZ 距离、共享行列/Cartesian 捕获和连续轨迹验证保持原合同。

## 命令与输出

```powershell
python examples/benchmark_zac_reuse.py --sizes 16 32 64 128 --depth 8 --workers 2 --output artifacts/zac-reuse/benchmark-large
python examples/benchmark_zac_reuse.py --sizes 16 32 --depth 8 --families butterfly random --bounded-spares --workers 2 --output artifacts/zac-reuse/benchmark-grid-new
python tools/audit_zac_benchmark.py artifacts/zac-reuse/benchmark-large
node tests/zac_reuse_viewer.cjs artifacts/zac-reuse/benchmark-large
python examples/zac_reuse_workbench.py --port 8769
```

打开工作台或 `http://127.0.0.1:8769/benchmark-large/index.html`。汇总支持规模、线路族和未完成筛选，点击每个 case 进入 reuse 开／关对照、完整 gate/Q 编号电路、跨层留驻 holder 和共用物理回放。大电路在固定高度区域滚动，仍包含全部门。“编辑输入”将完整 CZ、原子数、有界闲置轴选项和预算带回原编辑器，必须手动重编译。

`--timeout` 是单份本地规划/执行/录制的软预算（默认 600 秒），`--hard-timeout` 是包含作者子进程、独立重放和导出的进程上限（默认 1200 秒）。`--workers` 默认 2，范围 1–4。主机墙钟含校验和录制，不代表作者算法编译性能；并发和机器负载会影响它。

每个 case 保存两份 `upstream/placement.json`、作者 ZAIR/log、实际 plans、trace、initial/checkpoint、recording、物理/线路 HTML 和 worker 结果。汇总的 `benchmark.json` 保存全部输入、预算、随机种子、依赖环境与源文件 SHA256；`summary.csv` 分开提供准备、CZ、非复用归还、共同终态、作者前端秒数、本地执行/录制秒数和独立重放秒数。

相同代码/参数可用 `--resume` 接续。已完成的失败也是记录，不会静默重试或被成功覆盖。代码或合同发生变化时必须使用新输出目录。`status=finished` 仅表示整个批次已收集结果；单份 `completed` 才表示整条线路通过执行、效果、终态和独立重放。CLI 存在任何非完成项返回 2。

`tools/cancel_zac_benchmark.py OUTPUT --reason TEXT` 只停止输出目录精确匹配的 benchmark 进程及其子进程。已收集结果保留，尚无完整 worker 结果的项目写为 `cancelled`；取消不是物理失败或性能结果。该辅助工具使用 psutil。

## 第一轮暴露的规模限制

原 `build_batch` 把全部闲置 AOD 轴按 10 μm 间距添加到最右／上方。较大容量的小批次搬运会出现 `AXIS_BOUNDS`，即使所搬原子的源和目标都在世界内。原始结果保存在 `benchmark-large`，不可把此候选构造失败解释为物理问题无解。

有界闲置轴构造的独立函数在 `bounded_spare_axes.py`：保留被占轴的顺序与源/目标共同索引，在两端都可容纳的左、右和内部间隙安排禁用轴，间距仍严格超过硬件下限。先尝试 10 μm、再尝试 2.5 μm，最后才使用硬件下限加 0.01 μm，减少离散 corridor 候选因轴太密而消失。后续运输仍须通过现有完整物理验证，不从端点合法推断整条路径合法。该选项默认关闭，旧有序策略和原小例默认行为保持。

中间尝试只使用最紧间距，保存在 `benchmark-bounded`：14 项失败，另外 2 项被明确取消。它暴露了端点可行和整条路线可行的差别，不是最终推荐构造。最后在独立源码快照 `artifacts/zac-reuse/grid-source/` 中运行较宽间距构造，形成 `benchmark-grid`；相同环境与策略源码已接回主目录。之后主编排器仅补了取消项恢复时的耗时打印处理。

## 已执行结果（2026-09-21）

`benchmark-large` 为原运输器的 12 条线路、24 份运行：8 份重复配对完整通过，16 份复杂线路因有限运输候选未完成。四种规模的重复配对都有相同的并行几何/深度，含终态总时间均为 21299.470 → 3595.479 μs（减少 83.12%）。这只是正对照，不能当作一般电路的平均收益。

| 原子 / CZ | 重复配对装载原子次数（关→开） | 本地规划执行/录制秒数（关→开） | 独立重放秒数（关→开） |
| --- | ---: | ---: | ---: |
| 16 / 64 | 272→48 | 24.40→6.25 | 14.70→2.80 |
| 32 / 128 | 544→96 | 40.18→8.03 | 30.91→5.53 |
| 64 / 256 | 1088→192 | 96.75→19.37 | 73.09→13.13 |
| 128 / 512 | 2176→384 | 297.09→53.60 | 234.93→37.27 |

`benchmark-grid` 为有界/较宽闲置轴构造的复杂线路，8 份中 7 份完整通过。所有可比较行都包含同一初始终态恢复：

| 线路 | 原子 / CZ | no-reuse 总 μs | reuse 总 μs | 时间变化 | 装载原子次数（关→开） |
| --- | --- | ---: | ---: | ---: | ---: |
| 蝶形换伙伴 | 16 / 64 | 53294.970 | 33799.620 | −36.58% | 272→160 |
| 随机，seed=20260921 | 16 / 64 | 61434.983 | 44392.072 | −27.74% | 272→146 |
| 蝶形换伙伴 | 32 / 128 | **终态恢复失败** | 41552.119 | **不可比较** | — |
| 随机，seed=20260921 | 32 / 128 | 128809.089 | 97369.461 | −24.41% | 544→306 |

32 原子蝶形 no-reuse 的 128 个 CZ 都完成，随后在 `terminal return` 为 Q016 构造路线时耗尽候选；85778.265 μs 仅是失败前缀。不能用逻辑完成 73083.198 μs 或这个前缀和完整 reuse 时间算加速比。另一个仍可研究的问题是边缘 buffer 与满容量轴索引的组合；本轮没有放大世界或放宽任何物理条件来消除失败。

两批的主机整批收集耗时分别约 833.50 s、763.10 s，期间有并发与其他校验负载；不把它们当作专用空闲机器上的编译性能。改进构造在 64/128 原子的复杂线路尚未完整评估；当前最高完整证据分别是 32 原子随机、128 原子重复配对。

## 验证

- 原始批次和最终批次分别通过 `audit_zac_benchmark.py`：输入与初态一致、trace 门效果、ASAP 深度、物理阶段时间核算、驻留覆盖及完整终态字段。中间批次也核对了失败/取消记录，未把前缀重放成功改写成线路成功。
- 52 项相关测试、17 项原有有序路由回归通过；最终较宽间距更新后 26 项 ZAC/benchmark 测试通过。原本越界的 32 原子单原子运输负例在新构造下通过真实 Executor 与独立重放。
- 原始 24 份录制的 75 次 CZ、1680 个驻留区间，最终 8 份录制的 64 次 CZ、349 个驻留区间，通过共用 viewer 两种模式 32×、静态 holder 与 pair 距离等离线检查。失败录制仍只证明已执行前缀。
- 188 个 Python 模块的包边界检查通过。实际浏览器已检查汇总筛选、benchmark 导入编辑器、128 原子/512 CZ 门定位与两种模式终态；32 原子随机的完整 GUI 回放见本轮日志。

完整 AE 应用线路、混合 1Q、保真度、统计显著性与任意大规模线路的编译成功保证均不在本轮结论内。
