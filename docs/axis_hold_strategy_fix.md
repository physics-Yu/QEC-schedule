# 有序 AOD 路径策略修复：Q000 / 783 μs

2026-09-15。交付入口：http://127.0.0.1:8797/ 。原 8796 已打开的回放保留。

## 根因与修复层次

用户指出的是 `attempt2-direct-transfer/qec_ghz2/smt_ordered` 第一批 CZ 中的 Q000，伙伴 Q018 位于 (5,-55) μm，目标是 (5,-57) μm。旧出站轨迹：

```
(0,-60) → (2.5,-60) → (2.5,-57.5) → (7.5,-57.5)
        → (7.5,-57) → (5,-57)
```

`discrete_corridor_routes` 为起终构型构造严格相邻的网格入口，组合整组行列的入口、转角、出口。源坐标在网格上、目标纵坐标不在网格上时，直接 Y→X 构型不一定包含在这些模板里；目标列也随整组入口越过最终位置。预算再大也只能检查已生成的候选。这是运动策略候选不充分，不是后端要求先绕行，也不是 Rydberg 必须从某个方向接近。

策略包的 `motion/axis_hold_routes.py` 新增通用候选：

1. 直接 X→Y、Y→X，允许先沿源列脱离，再到目标列。
2. 对原有路径按 x、y 或双方向进行逐轴提前到位：某列/行跨过目标时在目标截停，后续可保持，其他轴继续运动。
3. 原有绕障候选保留；所有候选去重，直行合并，按真实后端运动时间排序。占据网格仅预筛选；完整连续扫掠、所有活动空交点、捕获闭包、SLM 支撑、精确 CZ 作用对仍由环境验证。
4. LOAD 已经撤去源 SLM 支撑。部分轴暂留时不伪造“所有原子已离开”的 transfer exemption；缺少合法 exemption 的段仍走普通完整验证。装卸与支撑规则没有改变。

共享规划器由 `motion_router=axis_hold` 选择，独立于硬件后端；贪心、SMT、SZ/EZ/MZ 群组运输均使用它。`legacy_corridor` 只供显式复现对照。算法没有 Q000、783 μs 或 GHZ 阶段特判。

同时按用户要求新增 `row_column_orthogonal` 后端配置：单个 MOVE 只改 x 列或 y 行；不变坐标全程保持，转弯拆段、三次运动段端速度为零。它继承原行列后端的序关系、扫掠与峰值约束。**保持某一列不是新增物理能力，原 `row_column` 已允许；新增后端只是将正交原语约束显式化。** 它不负责搜索。

## 尚未解决的策略问题

候选仍有限，未实现任意联合行列构型空间的完备最短路。若原候选数为 R、路径长度为 L、行列总数为 D，新变换至多增加约3R+2份候选，生成量约 O(RLD)，去重后再受物理验证预算限制；没有展开指数级所有行列子集。

SMT 仍先最大化当前 CZ 批次数，再按端点几何近似成本选模型，并非最小化完整运输时间。新 SMT 仍比新贪心慢约2.28%的物理时间；同为17批并不意味着批次落点与动作相同。每批原位卸载/归还、空闲轴外延构造、跨批驻留与目标—路径联合优化仍有限制。

下一项可执行工作：把路径验证与实际运输成本反馈给 CZ 候选选择，针对固定 frontier 比较多个同批大小模型；再评估以完整行列构型为状态的有界图搜索。必须报告候选覆盖与预算，不能把“找到更短路径”写成“最短路径已证明”。
