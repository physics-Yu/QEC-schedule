# 统一线路编译与初态优化

2026-09-21，Demo 原可编辑工作台统一为：配置初态与平台 → 编辑电路 → 选择编译方式 → 点击一次编译 → 查看物理回放。

- **固定初态**：按当前布局执行原通用编译流程。
- **优化初态**：一个任务内编译当前布局基线，再并行评估不同初态，选择不慢于有效基线的候选。基线只在候选0编译一次；同一搜索内相同映射去重。
- 搜索预算及结束条件放在“平台与算法”的编译配置中。删除独立优化启动和独立停止按钮，统一使用线路区的编译/取消。
- 结果区仅显示基线/优化对照、有效数量及诊断。生成动画是对已接受物理计划的独立重放，不再调用规划器；因此仍有录制成本，但不是重新搜索。
- 同一服务会话内，完整输入与配置一致、且已有成功搜索时复用结果。缓存键涵盖电路、初态、平台、编译算法和预算、seed、候选域、结束条件；仅UI开关enabled不改变执行合同。失败/取消不复用，编辑门或配置会使缓存失效。不跨服务重启复用历史搜索缓存，旧结果链接仍可直接恢复动画。

不同候选仍需各自物理编译，这部分计算是当前真实时长优化所需。此改动消除了“先普通编译再点优化”的重复流程，不宣称已实现增量编译或代理估计替代完整执行。

`placement_search.enabled`是保存的编译方式。本文最初验收时新草稿为 true；截至 2026-09-22 当前配置为 false，初态优化须显式选择，支持 ordered_greedy / smt_ordered / zoned_ids，不叠加到原生 QMAP 的作者映射。旧输入缺失整个 placement_search 时保留普通编译，旧优化报告含该对象但缺 enabled 时按优化处理。专用 QEC demo 仍执行锁定方案。

## 20原子四层随机实例

生成器：`python examples/random20_depth4_studio.py`；可编辑输入：`configs/workbench/random20_depth4.json`。使用预先固定seed20260921，没有按编译结果选种子。

1. 20个H。
2. 随机完美匹配的10个CZ。
3. 20个随机H/X/Y/Z/T。
4. 另一组10个CZ，与前组不重复，联合交互图连通。

共60门：H24、X3、Y5、Z3、T5、CZ20。每层每原子恰好参与一个门，逐原子依赖深度均为4；两层匹配图是一个连通环。四层指逻辑深度，不是四次物理脉冲，也不是完整QEC协议。

平台为原工作台4×5顺序占据、8×8 AOD（64交点）、EZ四邻保护开启；允许SZ空闲5μm候选点。候选池256、完整评估16、4进程、每候选180s、stable结束。

| 指标 | 结果 |
| --- | --- |
| 完成门 | 60/60 |
| 有效候选 | 2/16 |
| 基线/最终选中 | 11255.340057 μs |
| 另一有效候选 | 11366.456956 μs，比基线慢111.117 μs |
| 初态优化收益 | 0%，保留基线 |
| 物理CZ脉冲批次 | 15批完成20个CZ |
| 装载/卸载 | 各16批 |
| 原子累计路程 | 2426 μm |
| 搜索＋录制墙钟 | 355.8777秒 |

失败：6个PATCH_EZ_CAPACITY（现有整体平移布局无法放入EZ）、8个ORDERED_STAGING_EXHAUSTED（有限运输组/路线搜索未找到合法入区方案）。这是当前placement候选与入EZ策略耦合不足的证据；不能据此认定这些线路物理上不可执行，也不能宣称自由初态已普遍带来收益。没有修改硬约束、换种子或隐藏失败。

验证：两份录制全部门恰好对应实际操作；30个实际CZ脉冲（两份合计）均检查2μm作用距离；两种播放模式32×结束、数据不可变。真实GUI20原子播放到60/60；小例真实单按钮编译后再次点击命中缓存。11项模块测试及旧编辑器实际JS/API的贪心/SMT回归通过。
