# 同型单比特门原生批次

2026-09-12，步骤3 attempt1实现；首次正式验收由主线程统一执行，本文不预先声明测试通过。

`ProgramBuilder` 的 `phase='program'` 任务可调用
`add(OperationType.RAMAN_ROTATION, label, gate_ids=(...))`。
一个批次只包含同一种 H/X/Y/Z/T、不同目标的门；量子跟踪模式仍拒绝 T。
它是一个固定1μs的操作，所有目标的DAG效果在完成时逐个且仅一次提交。

每个实际打光目标仍需存活、未测量、启用支撑、合法寻址区、已完成相关交接且与其他存活原子间距至少5μm。
AOD目标必须静止；单个批操作统一占用一次AOD_0，不能与移动或支撑切换重叠。
静态目标与不相关移动重叠时，所有批次目标均检查完整重叠区间的邻居轨迹。

条件假的目标只占用原子和CONTROL资源，不打光；真的目标占用RAMAN资源。
批次的`applied`表示至少一个目标实际打光，`applied_by_gate`和`applied_gate_ids`保存精确逐门决定。
开始和完成记录均提供这些字段、`input_gates`和`u_parameters_by_gate`；观察器必须按实际目标绘制。
混合真假条件仍只有一个1μs时隙，Raman忙时按实际光照区间并集计；全部false时Raman忙时为零。

本轮公平比较保留历史`aod_busy_time_us`统计口径：所有Raman操作，包括需要AOD_0锁的单门和原生批次，均不计入该指标。
因此它不是全部AOD资源锁占用时间的并集。真实锁占用可以从operation interval的resources重建；总物理时间与Raman忙时独立记录。
若后续统一修改AOD忙时定义，应单独重算所有比较方案，不能只让新批次计入而旧单门排除。

该并行能力是用户指定研究模型；没有新增光场、串扰、加热或设备保真度事实声明。
