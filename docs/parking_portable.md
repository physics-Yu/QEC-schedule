# Parking Lab：可分享、可编辑的离线方法演示

**当前策略为v2：** 朴素版保留已匹配轴，兼容批量优化已可选择；自动比较按行/列最少抓取批数，空位不约束，无目标行列不开。详见 [当前规则与新验收](parking_compatibility.md)。

2026-09-17 界面修订：用户要求保留原工作台与格点可视化，不采用独立产品式页面。当前恢复“实验参数 → 编辑原子与目标 → 原子执行回放”的原结构，直接内嵌项目共用 `NeutralAtomViewer`（网格、AOD交点、路径、原子详情、轴坐标、32×播放），新增 `parking_recording.js` 只做模板时间线到viewer格式的适配。红色目标/蓝色固定的角色配色全程保持；圆/菱形继续区分SLM/AOD支撑。闭合空SLM按分享版选项显示灰色虚线圈，真实启用状态仍保留在帧中。此修订不改变规划策略或模型范围。

直接打开 `demo/parking/index.html`。接收者只需现代桌面浏览器，不需要 Python、Node、服务器、仓库或网络。文件内嵌样式、脚本、默认配置和默认动作。页面没有网络请求、远程字体或外部依赖。

## 使用

1. 默认 10×10：43 个红色移动目标、42 个蓝色固定原子、15 个灰色虚线空圈。可选择其他预设，或用画笔点击/拖动修改占据。
2. 选择朴素逐行、逐列或兼容批量优化；可载入“兼容行 + 空位示例”。必要时展开 AOD 容量、停车偏移和整体位移。修改不会自动生成动作。
3. 点击“生成动作并回放”，随后在原共用格点组件中播放、暂停、拖动时间轴或逐步跳转。倍率最高32×。关键帧讲解仅改变观看节奏，模型时间不变。
4. “下载可编辑分享版”将当前配置、动作、说明、完整工作台重新打包成 HTML。对方保存后用浏览器打开即可继续编辑。JSON 导入/导出适合保存配置；不需要 JSON 才能使用 HTML。

## 构造式算法及边界

这是 Python parking 模板的浏览器实现，不是通用路径搜索器。逐行只沿Y停车新行并保留列，逐列只沿X停车新列并保留行；优化版一次拾取整组兼容行或列。已承载轴不关闭，共享轴联动；所有活动交点均显示，包括空交点。目标全部拾取后统一一次终态再整体X、Y搬远，保留AOD承载，不卸载。

前提：隔离、规则 SLM 网格；原子初始都在源 SLM；单 AOD 初始空载、全部交点关闭。每维1–16，AOD行×列≤128；目标使用的行/列数不超过对应容量。间距为5/10/15/20 μm，偏移 ε>1 μm 且 spacing−ε>1.01 μm；终点整体X位移超过源宽度至少10 μm，Y位移非负。非空外部障碍、未知输入字段和未实现优化策略明确拒绝。

此合同下路线是直接构造的；运行时不做贪心、不搜索路径、不调用完整 Executor 的通用连续碰撞审计。验收独立检查连续轴线扫掠（含空活动交点）、载原子间距、完整拾取闭包和终态。测试覆盖不等于任意几何/设备的证明。外部障碍、非规则网格、任意混合 holder、RF/光场/保真度不在此模块范围内；需要这些能力时使用完整环境工作台。

计时采用项目示例运动学：同步三次插值 u=3s²−2s³，每个正交段起终点速度为0；v=0.5 μm/μs、a=0.01 μm/μs²、jerk=0.001 μm/μs³，交接100 μs，轴开关1 μs。它们是示例参数，不是设备测量。动画交接期间显示双支撑，结束后才变为 AOD holder。

## 模块边界与维护

- 纯规划：`src/neutral_atom_strategies/motion/parking_template.js`，浏览器和 Node 共用；接口 `preset / normalize / compile / sample`，不访问 DOM 或网络。
- 视图：`src/neutral_atom_app/visualization/parking_portable.html`、`parking_portable.js` 沿用原参数/格点编辑布局，`parking_recording.js` 将模板转为共用viewer的只读展示数据；不伪造Executor/checkpoint验收。打包时直接嵌入维护中的 `viewer.js` 与 `viewer-shell.html`。
- 生成：`python tools/build_parking_portable.py`；维护者需要 Node，接收者不需要。输出 `demo/parking/index.html`、`artifacts/parking-portable/Parking-Lab.html` 和包含 HTML/说明的 ZIP。
- `tools/build_demo_bundle.py` 同步上述单页并更新 manifest。不要手工修改导出的 HTML 作为源码修复。
- 原 Python 模块和完整物理工作台同步实现v2；环境执行器和 RL 代码不由此模块修改。优化版只保证整行/整列模板内抓取批数最少，不保证总运动时间最优。

## 初版历史验证（v1，当前结果见v2合同）

- `node tests/parking_template.cjs`：188 组独立几何检查（2×2 三态占据穷举×两策略、随机10×10×四种间距×两策略、额外空轴稀疏例）；无外部依赖。
- 同一测试可追加已保存作业目录，比较既有 Executor 的每个动作、轴起终点和计时。本轮核对4份记录：两个10×10（含用户修改例）和2×3逐行/逐列；全部一致。
- `node tests/parking_portable_ui.cjs`：运行导出 HTML 内的实际脚本，以 DOM 替身验证编辑、显式生成、失败提示、32×到终点、导入/导出、分享文件重开后继续编辑；不等于真实GUI验收。
- 本机100次随机10×10规划，中位1.86 ms、P95 3.14 ms、最大5.07 ms；仅动作生成，非完整物理编译，也非不同电脑保证。默认44动作，拾取2201.624837 μs，总时间2776.544171 μs。
- 真实浏览器工具本轮返回 `nodeRepl.fetch request failed`，因此视觉布局和实际下载对话框仍待人工验收；不将 DOM 测试记为浏览器通过。
- 恢复共用界面后，`node tests/parking_shared_viewer.cjs` 对182个时间点逐原子核对位置、holder和源SLM开关；两个策略32×终态、角色颜色和完整网格通过。控制器独立测试编辑/显式生成/失败/分享重开；均是DOM/Canvas替身，真实浏览器连接本轮仍失败。
