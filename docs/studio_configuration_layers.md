## 哪些东西不应再作为用户选项

1. **重复的派生数值**：AOD 总容量由行×列计算，不应另填；实际 trap 绝对坐标由整体位置和偏移计算，不应与偏移同时维护；界面列编号也不是调度时间。
2. **混入通用列表的实验算法**：patch_symmetric / patch_greedy、row 实验和各 QEC 专用执行器依赖声明平台族或协议，不能以“推荐”之名随 GHZ 模板隐式替换。它们保留为实验实现，不再出现在自定义算法列表。
3. **同时改动几层的电路模板**：电路示例只写 gates；平台、原子数、布局和算法均保持。需要配套平台与协议的例子升级为顶部完整实验 demo。
4. **可编辑外观下的固定条件**：1Q 时长、CZ 距离、Clifford 读出协议、GHZ data/ancilla 数目等，分别是物理模型约定或 demo 合同，不应伪装成任意可组合参数。
5. **协议信息的多份编辑真值**：移除工作台中 GHZ patch 原点、QEC 模式、故障选择器等实验专用编辑控件；完整 demo 固定物理线路和配套协议。历史元数据仍用于回放和验证，不再产生第二套可编辑配置。
6. **主页面的工程参数与保存表单**：搜索预算、固定模型说明、命名保存和文件往返收进独立展开区。主流程只保留工作模式、初态、线路和明确的编译动作；没有自动编译。

没有删除必要的独立物理校验、Executor、提交 trace、checkpoint 或原子统计；这些负责正确性与追溯，不能因为界面复杂而去掉。兼容接口中的 flat compiler/budget 镜像仍暂时保留，后续须随输入版本迁移统一移除。

## 参数归属

| 参数/数据 | 谁决定 | 本轮界面与写入边界 |
| --- | --- | --- |
| 门列表 | 用户编辑 / 纯电路示例 / 导入 | 自定义可改；完整 demo 锁定。示例不改其他配置。 |
| 原子数、row/grid/shuffled 布局 | 用户 | 自定义初态配置；减少数量前必须处理引用超出范围的门。 |
| 布局随机 seed | 用户 | 仅随机映射时显示；普通模式不跟踪量子态，该 seed 不表示量子测量噪声。 |
| AOD 行数、列数、x/y 相对偏移 | 用户 | 平台配置，可独立保存。几何能表示，不等于当前规划器能服务。 |
| AOD 容量、绝对交点、初始占据映射、世界边界 | 计算派生 | 只读。容量=行×列；占据由初态布局生成，世界边界按布局及轴范围生成。 |
| 当前整体位置、行列启用、SLM 开关、holder、路径与并行时间 | 编译/执行产生 | 来自已验证计划和 Executor 提交；画布不修改这些数据。 |
| EZ 四邻停驻保护 | 用户物理平台选项 | 自定义可改，demo 按合同固定；关闭不取消避碰、支撑或激光距离校验。 |
| 编译算法 | 用户 | 通用目录明确选实现，跨电路保持。不存在按电路名称偷偷换策略。 |
| 时限、决策数、READY/站点上限、前瞻预算 | 用户 / 所选算法默认值 | 属于编译配置。仅显示相关参数；选择算法不修改电路或硬件。 |
| 固定 1Q 1 μs、CZ 2 μm、1Q ≥5 μm、5 μm SLM 候选间距 | 现有物理模型 | 只读说明；本轮没有修改。不是从 demo 或浏览器自动推导的实验事实。 |
| GHZ data/ancilla 数量、patch 几何、测量轮次、故障、反馈、译码及专用调度 | 完整 demo 配方 | 选择 demo 后统一载入、锁定。导入历史结果只读，不据导入数据宣称属于当前 demo。 |
| 每原子路程/门数/装卸/等待、全局耗时、量子验证结论 | 已执行记录派生 | 结果层，与用户输入分离。初始预览不能冒充执行结果。 |

## 两种模式与两类示例

**自定义模式**保留六种现有通用策略：贪心、关键路径、有限前瞻、逐门归还基线，以及单原子搬运的每门归还/驻留复用。这里“通用”指不依赖某份 GHZ 的门 ID、patch 阶段或译码协议；不是任意布局成功保证。简单串行搬运具有独立价值，保留在目录中。

**完整实验 demo**在页面最上方选择：四 H 并行、四逻辑酉编码 GHZ、两逻辑单轮 QEC、两逻辑多轮 QEC、四逻辑多轮 QEC。其初态、平台、门列表、协议、算法和预算全部锁定，服务端也验证完整规范化输入。看门和定位回放仍可用。返回自定义时恢复进入 demo 前的草稿；不把 68 原子专用协议偷偷降格成普通自定义线路。

**纯电路示例**在门编辑器内独立选择：全部 H、物理比特 GHZ、CZ 链、H/CZ/T 混合、全部 T、空线路。它们只替换门列表，数量适配当前原子数。物理比特 GHZ 使用 H(target)–CZ–H(target) 实现 CX，不是 surface 编码 GHZ；其四比特理想稳定子已独立验证。

完整旧输入没有 `studio` 字段时，后台兼容接口仍按旧合同处理；新 UI 将其显示为历史只读。这样既保留科研脚本与历史回放，也不把导入文件中的专用实现重新塞回通用下拉框。新自定义输入使用 `studio={mode:"custom"}`，demo 使用 `studio={mode:"demo",demo_id:…}`。

## AOD：相对坐标与规划能力必须分开

配置的两个数组是相对首列、首行的偏移：

`position(r,c) = pose + (column_offsets[c], row_offsets[r])`

例如 pose=(20,−30)，列偏移=[0,10,30]、行偏移=[0,15]，交点(1,2)是(50,−15) μm，共六个矩形交点。实际抓取还取决于对齐位置和启用行列；不能把这六个交点理解成六个独立可任意拖动的 trap。

硬件层 rigid 支持非均匀相对间距，但**当前自定义 M4 多交点规划器仅支持 1×N、10 μm 等间距**；两个单原子策略要求 1×1。二维/非均匀配套运输当前存在于 demo 专用实现中。工作台只接入 rigid；仓库另有 row_column 后端，并不等于已接入此通用编译流程。

本轮真实 GUI 首次测试 1×3、偏移[0,10,30]时，在旧能力边界得到 `MULTI_TRAP_PLATFORM` 停滞（0门、0μs）。没有修改物理条件让它过关；现将同一能力检查前移：允许几何预览/保存，明确显示不支持，禁用编译按钮，直接 API 请求也在启动 worker 前拒绝。原失败产物保留。选择合法单行等间距或单 trap 后可以执行。

## 实现分层及后续路线

```text
configs/studio/*.json + demos/*.json（目录 / 默认值 / 完整实验输入）
              ↓
studio_config（读取 / 校验 / 锁定实验配方）
              ↓
studio_model.js（纯电路示例）+ workbench UI（用户草稿）
              ↓
validate_input / resolve_compilation（规范化、模式与能力校验）
              ↓
现有 scheduler / compiler → 独立物理校验 → Executor
              ↓
trace / checkpoint → VisualRecorder / AtomStatistics → viewer
```

本轮完成配置入口分层、服务端锁定、纯电路生成、能力检查与界面精简。其余顺序建议：

1. **输入 v2**：把平台、初态、电路、编译设置改为真正的嵌套对象；提供一次性 legacy adapter。删除 flat mirrors、重复预算和按 layout 推断算法的兼容逻辑。验收要求旧输入转换后物理语义一致，电路/平台/算法分别往返不串层。
2. **显式能力接口**：让每个规划器声明支持的 backend、阵列形状、几何和门集；现在的前置能力检查是已有能力的适配层，不应长期手写两份规则。先统一候选/诊断接口，再把一般矩形运输从 demo 执行器抽成可复用服务。
3. **独立协议执行层**：电路生成、读出反馈、译码、最终 GHZ 验证与运输调度分离。只有完成接口与等价验证后，才能将 QEC 电路与通用算法自由组合；本轮锁定 demo 只是诚实隔离现有耦合，没有解决通用 QEC 编译。
4. **运行与报告拆分**：接续既有 A0–A8 方案，减少计划内重复 initial_dag/序列化，保留唯一执行真值；统计和回放按 trace 派生。性能优化以阶段计时和相同执行合同做对照，不删除必要验证来换速度。

以上 1–4 尚未完成，不应把界面清理当作底层架构迁移已结束。本轮验证和访问方式见 [交接日志](../instruction/logs/2026-09-14-studio-layers.md)。
