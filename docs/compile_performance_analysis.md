# 编译耗时分析与优化方案

日期：2026-09-13。状态：分析完成，优化未实施。对象为当前四逻辑 GHZ / 68 原子 / 1868 槽 / 7×14 AOD 的已交付案例。此次只增加诊断脚本、证据和方案，没有修改生产编译器、物理模型或已交付动画。

## 结论与证据强度

“黑名单”若指先提候选再拒绝非法候选，确实有优化空间；但不是小时级耗时的完整解释。若指 EZ 四邻禁停规则，此案例输入中 `ez_neighbor_guard_enabled=False`，该规则已经关闭，不能归因于它。

当前路径层已经有有界半格图 A*、Manhattan 启发式、无障碍最短路线通过精确校验即早停、单次搜索的边缓存。上层也已经按相同位移、行列和隔行矩形构造候选，并有装载闭包与作用对 preflight。不是完全无结构的随机搜索。

主要问题是：完整当前状态与冗长历史耦合；同一个候选在构造、审计、提交和执行时多次做相同工作；物理与量子几何内核中仍有大量全体扫描。构造式合法候选应推进，但应与这些工程问题分别处理。

## 代码中的成本来源

1. `motion/compiler.py::fingerprint` 散列 `state.snapshot_data()`，其中含完整 trace、全 DAG、线路、world、量子态、队列等。`snapshot_encoding.py` 缓存了不可变 trace 的转义编码，但每次 digest 仍处理完整编码历史。历史持续增长时，重复扫描有累积成本。不能把已有编码缓存说成没有缓存，也不能认为扩大缓存已经解决所有增长成本。
2. `ProgramBuilder.finish` 预测后调用 `audit` 生成元数据，再调用 `exact_validate`。实际提交还经过 `Executor.submit`、pending start 的 runtime 检查和 `reduce_program` start 检查。前三个保存计划的独立执行各测到 3 次 `validate_program`，尚未算原本编译构造的审计。
3. `Executor.step` 前后调用 `validate_runtime`；后者先扫描全部 trace，scheduled 分支再次扫描。`validate_program_runtime` 解析计划、构造时间线、比较当前计划的事件前缀。**已有 `_expected_prefix` 增量重建缓存**，所以不能声称每次都无缓存重放全部物理历史；不过全 trace 扫描、计划反序列化、比较和大对象缓存键仍重复。
4. `run_qec_joint` 为保持原基线次序，先构造并验证 restoring reference，再构造 retained pulse。readout 也先构造 reference，再构造 loaded 版本，随后双方再次 audit 比较。这是有意的正确性保护，但缺少可复用的几何与审计产物。
5. `single_trap.route` 对同一路线先在 trial builder 应用，再向实际 builder 逐操作再次应用；更外层仍独立审计。可复用私有预测结果，但不能让 planner 直接提交 live state。
6. `rigid_aod` / `dynamic_traps` / `slm_clearance` 对线段逐对检查携带原子、静态原子、开启 SLM、活动空 AOD 交点。通道已限定，但检查实现仍为大量 Python 循环。每次构建派生 `SimulationState` 还执行结构验证，扫描整份线路等未变化数据。
7. `StabilizerState.apply_gate` 每个 H/CZ 都创建新对象；构造器检查所有生成元对易及独立性。43 个同类 H 批次内部仍逐门进行全量合法性验证。这里没有使用 2^68 幅度的通用态矢模拟；不应把慢解释为必然的指数状态空间。
8. viewer 已用原子差量记录，但 `VisualRecorder.observe` 仍扫描历史 operation 更新测量显示，扫描全 DAG 生成状态摘要。可优化，但本轮无 recorder 的执行样本仍慢，证明它不是唯一原因。

## “白名单”应该放在哪一层

应是随当前状态生成的合法动作域，而非写死某份 GHZ 的动作序列。

对于固定 AOD pose，设开启行集 R、列集 C，实际活动交点为 R×C。抓取三个角可能同时开启第四个角；第四角若有不允许附带携带的原子，就必须在选行列阶段排除该组合。即使第四角空着，也仍要计算这个活动空阱的全程扫掠。

可把每一行允许的列集合编码成 bitset，在组合行时取交集，提前满足容量、轴对齐、捕获闭包和不携带锚点等必要条件。相同位移的 READY 门归组后，按这些约束直接构造闭合矩形。冲突不是永远能用两两不兼容图表达：完整 Cartesian 闭包与全局 CZ 实际作用对还需要集合级约束。

当前 7×14 仅非空行列掩码就有 `(2^7-1)(2^14-1)=2,080,641` 种，再乘 pose、holder、SLM masks 等状态。预生成“所有合法配置白名单”可能比按需搜索更贵。建议只缓存局部模板和频繁出现的几何子问题，保留受预算约束的通用回退，并明确候选范围。

CZ 的合法域还需满足：相互独立的 READY 操作数、同一平移能实现的配对、完整 EZ 中实际作用对恰好等于声明门对。1Q 则按同类型、READY、稳定支撑、已确认距离条件及资源可用性求合法目标集合。合法终点也不等于合法路径，必须另检整段扫掠和交接边界。

## 建议的优化顺序

| 顺序 | 工作 | 应保留的正确性边界 | 验收重点 |
| --- | --- | --- | --- |
| P0 | 分阶段计时、调用计数、拒绝阶段、hash 字节量、cache hit/miss、RSS | 不改变行为和候选次序 | 首/中/尾段分别测量；避免累计时间相加 |
| P1 | 静态 circuit/world 编码与解析结果复用；DAG 起态解码和 schedule 的有界不可变缓存；重复引用用紧凑索引 | 相同值相同字节、输入内容变化失效 | 旧 trace/checkpoint 逐字一致，篡改仍拒绝 |
| P2 | 原子/SLM 空间索引和精确线段候选筛选；固定几何结果复用；批量 Clifford 变换 | 不变的半径、空阱扫掠、所有交点、同类光规则、完整批次效果 | 与原全量检查器逐候选对照，含边界反例 |
| P3 | 当前状态、执行历史、静态定义分层存储；增量运行审计与历史完整性摘要 | stale plan/错误队列/篡改历史不能被缓存掩盖 | 新格式迁移、恢复/分叉、随机篡改差分核验 |
| P4 | 构造合法 masks/cohort、复用路线图和已核验边、两级候选评分 | 候选规则独立于具体电路；最终完整计划验证 | 非对称/随机线路成功率、候选数量、墙钟时间、物理总时长 |
| P5 | 在小窗口用约束求解改善调度，复用重复 syndrome 结构 | 测量依赖/条件反馈/终态/全局光冲突保持 | 同输入平台终态的物理 makespan 对照，报告最优性边界 |

P1/P2 是可局部推进的工程改进；P3 涉及指纹格式、checkpoint 表示和验证信任边界，属于需单独评审的大框架方案。当前仅提出，不实施迁移或减少安全检查。P4 可先在现有接口中实现，优先级可按 P0 结果调整；没有必要等待一次大重写才改候选。

### 状态与审计：必须避免的错误缓存

当前 `state.version` 不足以作为唯一键：例如排入队列时版本不变，预测状态与原状态也可能共享版本；恢复或不同分支同版本但内容不同。直接 `cache[version] = valid` 会隐藏陈旧计划和篡改。

低风险阶段先缓存不可变值的编码、解码和静态图，保持原 canonical bytes 与完整审计。后续设计分开保存：不可变 circuit/world；placement、masks、DAG runtime、量子态/RNG、队列、资源等当前状态；append-only 历史。每个计划引用静态定义及紧凑运行起态，不再把整份静态门定义重复塞进 `initial_dag`。边界验证仍覆盖所有与合法性有关的当前字段。

若用历史 hash chain / 分块摘要替换完整历史扫描，需要定义有序、长度明确、带域标识的编码并版本化。**它不等于原 `sha256(canonical_full_snapshot)`，不能承诺兼容旧 plan ID/指纹。** 现有 snapshot 中 trace 前面也有变化字段，不能简单把旧 SHA 对象 copy 后追加 trace 来保持原全快照 hash。可先保留旧 checkpoint 导出和完整离线校验，再单独评审新格式。

增量核验应保存独立验证器的期望状态并核对每个新事件的效果、时间和资源；导入/恢复/首次跨信任边界仍做完整核验。不能把“这是自己刚生成的计划”当作无需验证的许可，或让新增缓存成为第二个 live-state writer。

### 路线：更适合固定 rigid AOD 的方案

固定 masks 与相对 offsets 时，AOD 是一个整体平移的多点 footprint，可把障碍变换到 AOD 原点配置空间。对每个携带点/活动空点，把相应障碍按 offset 反向平移并按其真实 clearance 膨胀；行列边界、SLM 空阱规则、depart/approach 绑定例外分开处理。这种配置空间建模有成熟依据，不能简单用整个矩形包围盒替代所有点而牺牲穿孔通行能力。[配置空间课程材料](https://courses.csail.mit.edu/6.141/spring2013/pub/lectures/Lec12-ConfigurationSpace.pdf)

具体先做：固定 world/footprint 的半格通道拓扑缓存，起终点接入口按请求加入；边状态区分 UNKNOWN/VALID/INVALID。先求短路线，只检查本路线的未知边；失败后局部更新图，再求路，不预先校验全图。跨请求只有几何、masks、holder、活动空交点、相关邻点预约和交接权限完全适用时才复用。当前 A* 已有单次最短路线先验早停，新增价值是跨请求复用和精确几何内核加速；不必先换成随机采样规划器。OMPL LazyPRM 的惰性碰撞检查与多查询复用提供可参考的机制，并非本项目可以直接省略碰撞模型的现成替代品。[OMPL 官方文档](https://ompl.kavrakilab.org/core/classompl_1_1geometric_1_1LazyPRM.html)

固定 rigid 的同一图内最短运输距离，不等于电路最短完成时间；动态 row_column 变距会改变配置空间，不能复用二维整体平移的完备性声明。

### 几何内核：减少需要做精确计算的原子对

水平段先取 x 扫掠范围和 y±clearance 的窄带，用索引查出可能接近的点，再保留原精确 `segment_clearance` 与容差判断；垂直段同理。只有远离扫掠包围盒的点能安全排除。索引覆盖活动空阱、存活静态原子和开启 SLM，不能只索引门操作数。几何状态变化时更新索引，避免每段重建。

rigid 携带原子之间相对距离恒定，可在 capture/mask/geometry 变化后核验一次并复用结果；静态场和交接例外变化仍须重检相应内容。先用纯 Python 索引和批量数值计算与旧内核对照；若热点仍在数值核，再考虑编译扩展。直接改语言无法消除反复处理几百 MB 历史的算法成本。

### 量子层：批次变换，而非每个目标重验整个 tableau

同类独立 H/CZ 批次可一次作用于生成元数组，再验证一次完整批次结果，保留声明的所有门效果和确定次序。外部构造/恢复仍检查生成元合法性。测量与 reset 的投影、RNG 和报告位分离必须保持原语义，不把未知测量结果预填入模板，也不把条件 false 的控制时间静默删除。

这种方案无需换量子模型。引入第三方 tableau 引擎应另做相位约定、生成元表示与测量 RNG 对照，不能用“同一 seed”替代逐分支验证。

### 调度：先有可执行解，再在预算内改进

当前 `qec_cz_groups` 先按 batch 大小、位移排序，`run_qec_joint` 接受第一份通过的 reference，再尝试驻留复用。它不是对所有候选求最小总工期，也不是无界组合最优搜索。候选数量上限大，不意味着每次都用满。

建议两级选取：第一层用合法域、传输距离下界、装卸下界、关键路径与下一轮 cohort 复用评分；第二层仅对少量可能改善当前最优解的候选做完整路线与计划构建。采用下界剪枝时必须与同一目标比较，不能将“每门平均成本”当成剩余整线路 makespan 的严格下界。

保留当前可行解作为 incumbent，预算内搜索更好解，超时返回已完整验证的 incumbent，并明确优化未完成；若还没有完整可行解则报告阶段/预算/原因。不要把仅编译前半段冒充整线路成功。

对重复 surface syndrome 层，识别 DAG 子图与几何位移模式，缓存可参数化的行列掩码、装卸路径和服务骨架；每次重新绑定实际 qubit、测量依赖、状态前置条件并验证。这样优化器仍接受任意受支持的编辑线路，而非识别 GHZ gate ID 后播放脚本。

在这些候选服务之上，可以用小窗口 CP-SAT 选批次并安排资源不重叠的时间区间；几何 feasibility 继续由独立后端给出。OR-Tools 的 job-shop 示例提供依赖与 `NoOverlap` 的表达，不会自动解决本项目的 Cartesian 捕获闭包、全局 CZ 串扰或移动障碍。[OR-Tools 官方示例](https://developers.google.com/optimization/scheduling/job_shop)

## 分阶段验收，避免又等一小时才发现问题

1. 保留本轮前三计划及完整原 trace 为只读参考；增加早/中/末状态的短服务样本。所有样本记录冷/暖缓存、工具开销和运行环境。无插桩计时至少重复三次，分别报告中位数和范围。
2. 序列化/缓存/内核等不改调度的优化，要求同输入逐事件、量子态/RNG、终态以及兼容范围内的 checkpoint 字节一致；插入 mask/队列/holder/历史篡改反例，证明缓存不会漏检。
3. 几何/动作域单测覆盖三角捕获、隔行抓取、非均匀轴、空交点扫掠、5 μm 1Q 边界、四方向 CZ、拥堵与无路、邻点禁停开关及允许经过。候选域可以不完备，但必须报告边界，不能把未搜到写成物理不可能。
4. 使用普通随机线路、非对称布局、两块与四块 QEC 的固定矩阵。优化调度时允许 trace 改变，但必须保留所有逻辑依赖/效果、读出与纠错语义、物理约束和终态。测量顺序改变时不能仅比较 seed 下单次结果；第一阶段先冻结测量顺序以便精确对照。
5. 同时报编译墙钟、求解成功率、峰值内存、候选数、精确几何调用数、物理 makespan、装卸次数和实际并行度。编译快但物理执行显著退化不能冒称全面进步。
6. 小样本过关后再做一次完整 1868 槽编译和独立核验，最终真实浏览器检查可编辑重编译与完整回放。没有实测前不承诺“70 分钟变几秒”或固定加速倍数。

本轮未做生产优化、未运行完整编译基准、未实施 schema/指纹迁移、未修改物理约束。下一条可执行任务是 P0 阶段计时与 P1 字节兼容的静态/不可变数据复用，再用本轮样本对照。
