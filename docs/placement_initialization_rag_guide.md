# 中性原子编译器的 Placement 初始化：文献依据与实现指南

日期：2026-09-21。依据：本地 `qecschedule_RAG` 的已收录原文、证据图，以及当前 QEC-scheduler 源码。本文讨论通用物理电路，不涉及 QEC code 设计。

**建议采用的结构是：固定平台与执行合同 → 提取电路交互及阶段信息 → 生成多个合法初态 → 用运输感知代价搜索 → 对少量候选做完整物理编译 → 返回实际完成时间最短的有效初态。**

初始化的任务是提供一个有利于后续执行的起点。它的好坏必须结合后面的 placement、routing 和 scheduling 判断。把交互频繁的 qubit 放近，是候选构造方法；真实优化目标应由完整执行结果定义。

本文用三种标记区分证据：**[文献]** 表示所引原文支持；**[现状]** 表示本次读取当前源码确认；**[建议]** 表示综合文献提出的设计，尚未因本文而实现或验证。RAG 的 `accepted` 表示证据审阅通过，不表示独立复现。

## 1. 先确定初始化可以改变什么

建议当前主问题固定为：**在给定合法 SLM 站点集合中，为每个 qubit 选择唯一初始站点，允许使用空位。**

| 问题 | 决策变量 | 与本文的关系 |
| --- | --- | --- |
| 物理几何设计 | trap 的连续坐标、区域形状、间距 | 上游问题；Parallax、Qompose 提供参考 |
| 初始 placement | qubit → 已给定的 SLM 站点 | 本文的主问题 |
| 动态 placement | 每一阶段的目标位置、卸载位置、驻留选择 | 下游问题；会影响初态的价值 |
| 初态装配 | 怎样把实际装载的原子搬成所选初态 | 单独的物理过程；当前运行目标不包含它 |

允许从全部合法站点中选择，可以改变原子占据的形状；这仍不同于任意新建 trap 或改变平台边界。仅在原占据点上交换 qubit，搜索域则更小。比较算法时必须声明使用哪一种搜索域。

记 qubit 集合为 Q，允许的初始站点集合为 S，初始化映射为 M₀：

\[
M_0:Q\rightarrow S,\qquad q\ne q'\Rightarrow M_0(q)\ne M_0(q').
\]

固定某些 qubit 时另外加入 `M₀(q)=locked(q)`。映射改变的是环境建立前的初始 holder；运行中不能通过改字典瞬移原子，也不能混淆物理搬运与逻辑 SWAP。

## 2. 文献中可以直接借鉴的部分

| 来源 | 实际方法 | 对初始化的用途 | 适用边界 |
| --- | --- | --- | --- |
| **ZAC，P05** | 模拟退火；交换两个 qubit 或迁入空 trap；代价考虑到纠缠位置的移动、同行运输及早期门权重 | 最直接的初始化算法主线 | 代价是估计，不是完整路由时间；同行规则依赖其目标 trap 结构 |
| **Routing-Aware Placement，N002** | 每层 placement 使用 A*；按兼容移动分组估计重排时间 | 改进初始化的前瞻评分，让候选考虑搬运分组 | 原方法主要处理动态 placement；用于初始化是本文建议；部分启发项不保持可采纳性 |
| **Parallax，N110** | 交互图 → GRAPHINE 双退火坐标 → 硬件约束离散化 → SLM/AOD 选择 → 调度 | 构造交互图种子，并关注移动空间 | 连续拓扑及其离散化方式不能直接当成当前固定平台的动作能力 |
| **Atomique，N001** | SLM 映射关注行列负载均衡，AOD 映射对齐高频交互伙伴 | 构造强调并行性的另一类种子 | SLM/AOD 阵列分工与当前初态全在 storage 的模型不同 |
| **Qompose，N117** | 根据电路特征从三种拓扑中选择，再进行映射 | 说明应保留多种形状候选，且选择依赖指标 | “optimal”限于候选拓扑，不是所有连续布局的最优解 |
| **Application-Specific Layout and Hub-Assisted Shuttling，N005** | 电路专用布局后加入空 hub，结合搬运生成计划 | 提醒候选不要耗尽临时中转空间 | 假设局域 Rydberg 寻址；本文不引入其新 trap 或寻址能力 |

来源：[ZAC §V](https://arxiv.org/html/2411.11784v4#S5)、[Routing-Aware Placement](https://arxiv.org/html/2505.22715v1)、[Parallax](https://arxiv.org/abs/2409.04578)、[Atomique](https://arxiv.org/html/2311.15123v3)、[Qompose](https://arxiv.org/abs/2409.19820)、[Hub-Assisted Shuttling](https://arxiv.org/abs/2605.29964)。本地版本与页码见第 11 节；具体事实以本地所列版本为准。

**[文献] ZAC 的关键启发：** 初始化不是只最小化两个 qubit 之间的距离，而是估计把它们送到纠缠位置的代价。其参考几何下，同行伙伴可以由同一 AOD 行搬运，采用较长移动的代价；异行伙伴不能同时卸到同一目标行，采用代价之和。它还降低较晚阶段门的权重，因为动态 placement 会逐渐使初态位置失去预测价值。退火邻域包含交换与迁入空位。[P05，PDF 第 4–5 页]

这里有一个重要的模型差异：ZAC 倾向让某些交互伙伴同行，而 Atomique 的 SLM 映射强调行列负载均衡。两者对应不同的运输和门实现方式。初始化规则必须由当前 backend 的可执行动作决定，不能把论文中的几何偏好合并为普遍定律。

## 3. 输入、输出与优化目标

### 3.1 输入必须完整

1. **电路 C**：稳定的 gate/qubit ID、门类型、完整依赖；即使只对 CZ 计几何分数，也保留 1Q、测量、reset 和经典控制依赖。
2. **平台 H**：合法站点与区域、AOD 行列容量和运动规则、初始轴配置、开关、装卸时间、作用条件、安全间距。
3. **基线 Mbase**：用户实际选择的初态，不默认替换为顺序布局。
4. **候选域与锁定条件**：哪些站点允许使用，哪些 qubit 不允许换位。
5. **下游编译器 π**：明确算法、版本、选项、随机种子和每候选预算。
6. **终态合同 Θ**：固定绝对终态，或完成全部服务后的合法稳定态。

### 3.2 真正选择结果的目标

**[建议]** 固定 C、H、π、Θ 后，定义：

\[
M_0^*=\arg\min_{M_0\in\mathcal V}
T\bigl(\operatorname{Compile}_{\pi}(C,H,M_0,\Theta)\bigr),
\]

其中 V 是已完成编译、物理校验和独立重放的有效候选集合。T 是模拟的物理完成时间，包含合同要求的服务收尾；搜索所花的计算机墙钟时间另列。

这得到的是**当前编译器与预算下，已验证候选中的最好结果**。搜索超时或有限路由失败不构成物理不可行证明；即使穷举全部初态，若内部 routing 是启发式，也不能据此宣称硬件全局最优。

初态装配成本有两种可选合同，应在实验前固定：

- 已准备初态：只比较运行阶段；当前程序采用这一合同。
- 从共同装载态开始：比较 `Tprepare(M₀) + Trun(M₀)`，准备过程也必须真实规划执行。这是后续扩展。

### 3.3 输出至少包含什么

输出映射、基线及胜者、代理分数及分项、完整完成时间、编译/重放墙钟、有效与失败候选数、失败原因、搜索种子、平台/电路/编译器/终态指纹、实际计划与初末快照。

基线有效且没有更好结果时保留基线；基线无效但找到有效候选时报告“找到可执行初态”，不计算相对无效基线的加速比；全失败时返回 `no_valid_execution`，不伪造最优布局。

## 4. 电路应同时保留图与时间信息

### 4.1 加权交互图：快速构造种子

令 wᵢⱼ 为电路中 qubit i、j 参与双比特门的次数，构造 G=(Q,E,w)。对当前 CZ 电路，它就是 CZ 次数。

简单距离分数为：

\[
J_{\mathrm{pair}}(M)=\sum_{i<j}w_{ij}\,d(M(i),M(j)).
\]

**[现状]** 当前自由初态搜索使用曼哈顿距离。这个分数适合快速生成候选，但忽略了到 EZ 的距离、时间顺序、同时拾取的干扰及装卸分组。其单位是加权距离，不是 μs。

### 4.2 依赖阶段：为初始化提供前瞻范围

**[建议]** 从完整 DAG 产生参考阶段 L₀,L₁,…，在前 K 个含 CZ 的阶段估计运输。参考阶段用于评分，不锁死下游调度顺序。不能只对交互图做无条件边着色后，将得到的层直接当成原电路的合法门序。

保留两种描述：全电路交互图用于种子；依赖阶段用于前瞻评分。含测量及条件分支的电路还应声明评分使用哪个分支或场景集；未建模的部分交给完整评估，不能声称代理覆盖它们。

可对阶段使用 αₖ=ρᵏ，0<ρ≤1。它是建议的超参数形式，**不是 ZAC 原公式**。若下游每批都返回初始 storage，远期门仍反复受到初态影响，ρ 应包括 1 的对照；若支持动态放置，短前瞻更有理由。不能机械复制早期权重。

## 5. 推荐的三层评估

### 第一层：合法映射与廉价预筛

检查 ID 完整、映射单射、锁定点、站点域、初始支撑与开关一致性。几何初态检查交给现有环境验证。

之后可加入**与当前构造算法绑定的**预筛，例如：某个候选搬运模板使用的行列数是否超过 AOD 容量；其目标构型能否容纳于 EZ；指定整组平移是否满足区域边界。

这些检查要保留原因及作用范围。“整批装不下”只能拒绝该整批模板；允许拆批时不能直接判定整个初态不可行。拾取闭包、连续轨迹和额外作用对仍需物理编译核验。

### 第二层：运输感知代理

**[建议]** 在简单距离之上，分两步提高评分质量。

**A. 到纠缠目标的成对代价。** 对门 g=(i,j) 和候选纠缠位置 ω，估计两条运输的耗时 τᵢ、τⱼ；已知所用运输模板允许并行时取 max(τᵢ,τⱼ)，否则按模板的顺序累加。目标选择应考虑平台实际 gate 构型，不能让两个原子占同一 trap。

可构造：

\[
J_{\mathrm{access}}(M)=\sum_{k<K}\alpha_k
\sum_{g\in L_k}\min_{\omega\in\Omega_g}c(g,\omega,M).
\]

这是**本文建议的简化代理**。各门独立取最小值会忽略目标争用；ZAC 原文用其特定规则选择参考 Rydberg site，并非上述任意目标最小化。若再加入门到 site 的匹配，也只解决位置争用，尚未解决整批 AOD 运输兼容性。

移动时间函数应来自当前 backend。ZAC 使用与距离平方根相关的近似；本项目已有速度、加速度及 jerk 限制下的分段时间估计，不能用论文近似替换项目物理规则。

**B. 兼容分组代价。** 为参考阶段构造目标分配，再根据当前 transport 模板把操作分成可并行组 B。对单 AOD、组间串行的近似，可写成：

\[
\widehat T_k=\sum_{b\in B_k}
\left(\widehat T_{\mathrm{position},b}
+\widehat T_{\mathrm{load},b}
+\widehat T_{\mathrm{move},b}
+\widehat T_{\mathrm{offload},b}\right).
\]

每一组的移动时间按共同轴轨迹估计，不能简单累加所有原子的距离。对正交分段，先估计每段，再按执行次序累加；只有同一段内兼容的动作才可以取最大值。组数、装卸次数和空 AOD 定位都影响代价。[设计依据：N002；公式为本文建议]

注意三个边界：

- 拾取分组不等于完整 route 分组；卸载、停车、重新抓取也可能拆组。
- 允许多 AOD 或跨组重叠时，组耗时之和不再等于 makespan，需要资源调度。
- 所有未来层都从 M₀ 计算是静态代理。模拟动态驻留时必须同步推进预测 holder、空位和 AOD 状态，否则会重复使用不存在的资源。

初版建议只选择一种量纲一致的运输代理作为搜索主分数，并保存分项。不要直接把“微秒＋微米＋冲突个数”相加。确需组合时，先归一化并用独立数据确定权重。

### 第三层：完整物理执行与独立重放

对 shortlist 中每个映射创建独立初始状态，运行同一个下游编译器、相同预算和终态合同。验证实际门执行、支撑/开关、活动交点、额外捕获、真实作用对、全程运动与服务收尾，再重放已接受计划。

只有通过这一级，才能依据 T 更新“最好结果”。代理更低、门层数更少、路径端点合法都不足以替代完整评估。测量电路使用分支和理想量子态时，还要保留对应协议/语义检查；通用几何通过不是 QEC 协议通过。

## 6. 候选生成与搜索算法

### 6.1 同时保留几类种子

**[建议]** 基线始终保留；其余种子包括：

- **交互紧凑种子**：从高加权度 qubit 开始，优先放与已放 qubit 联系强的节点，多选空间锚点。
- **早期门与 EZ 接入种子**：把前几阶段经常使用的原子放到较易运输到 EZ 的区域。
- **运输兼容种子**：按当前抓取模板组织行列，并为活动交点闭包和旁观原子保留空间。
- **负载分散与空位种子**：尝试不同的行列占用、空闲通道和整体位置，避免只搜索一种紧凑形状。
- **随机种子**：固定 seed，提供结构不同的候选作为探索和负对照。

其中后三类的具体实现需要 backend 约束支持；不能因提出了这些种子名称，就认为它们已证明可路由。对小 shortlist 可按映射汉明距离或占据形状分桶保留多样性，避免全部预算花在相似布局上。

### 6.2 退火适合便宜代理，完整编译适合外层选择

采用交换、迁入空位，以及合法时的整行/整列交换、块移动作为邻域。所有操作都只生成新候选，不改变运行态。

代理退火接受更优解；对差值 ΔJ>0，以 exp(−ΔJ/Tsa) 接受。温度与 J 使用一致量纲，可根据一批邻域正差值的尺度初始化，再按预算降温。温度、重启数和邻域比例都属于实现超参数，无统一论文最优值。

同时维护两份结果：`best_proxy` 与 `best_verified`。退火当前状态可能变差；对用户交付的 `best_verified` 必须保留最好有效结果。

以下是**建议流程伪代码，不是可直接调用的新 API**：

```text
输入：电路、平台、基线、候选域、固定编译/终态合同、预算
评估基线，保存有效性、实际时间及失败信息
建立交互图与参考依赖阶段
构造多类合法种子，将基线加入候选档案

while 尚有完整评估预算：
    从种子或已有好候选生成交换/空位/块移动邻域
    检查映射及所用模板的必要条件
    用运输代理执行有界局部搜索或退火
    去重，选低分且有差异的候选，并保留探索名额
    在独立环境中完整编译、执行及重放这些候选
    保存失败；只有有效且实际完成时间更短才更新 best_verified

返回 best_verified；若不存在则返回全部失败诊断
```

先缓存 qubit 对权重、站点距离、映射评分，再考虑复杂搜索器。缓存完整编译结果必须包含电路、平台、编译器版本与选项、候选初态、终态及随机种子；不能跨合同复用。

## 7. 一个四比特例子：为什么交互距离不足以判断

设四个合法 storage 站点为 2×2 方格，相邻距离 a。电路先执行 L₀={(q0,q1),(q2,q3)}，再执行 L₁={(q0,q2),(q1,q3)}，依赖保持该顺序。

```text
布局 A                 布局 B
q0  q1                 q0  q2
q2  q3                 q1  q3
```

两个布局的全电路加权曼哈顿距离都是 4a，简单交互图分数完全相同。A 让第一层伙伴同行；B 让第二层伙伴同行。

在 ZAC 所讨论的“同行伙伴可共同送到一个横向 gate site”的运输规则下，两者对前后两层的成对运输估计不同。若第一层更重要，或者执行第一层后会重放置，A 就可能更合适。若每层总返回原位置、两层权重相同且平台对称，也可能仍然打平。

**这只是展示信息损失的解析例子，没有在当前程序执行，也不证明 A 的总时间更短。** 两对门能否同时运输仍取决于 EZ 目标、活动交点、轴顺序和路径。它说明应把阶段与运输模型交给评分，而非仅改变优化器名字。

**当前自由搜索仍使用交互距离排序，并不调用 `PlacementCostModel`。** 后者的存在说明已有可复用的代理实现，但两条搜索路径尚不能混为一谈。

当前工作台新草稿配置是候选池 256、完整评估 16 次、4 个 worker、`stable` 结束；16 次包含基线和失败，256 不是完整物理执行次数。低层 `CompilerSearchConfig` 默认仍为 12 次/64 池，执行 API 默认为单 worker、`fixed`，因此调用方要显式传参。

`stable` 取消末尾恢复原 layout，但仍完成已接受服务，包括现有每批 CZ 的返回/卸载；它不是在最后一个光脉冲结束时截断。`fixed` 要求共同绝对终态。详情见[并行初态优化](parallel_initial_placement.md)、[统一编译流程](unified_compilation_workflow.md)。

程序已经具备有用的研究底座。下一步优先检验：**相同候选与完整编译预算下，加入 EZ 接入和运输兼容信息，能否提高有效率、改善候选排序，并降低实际总时间。** 这比单纯扩大候选池更能回答初始化方法是否有效。

## 9. 建议按三个阶段落地

**阶段 A：先做评分诊断。** 对已保存、合同一致的候选计算距离代理和已有运输代理，关联其实际完成时间与失败原因。有效候选计算排名相关性、top-k 命中和最好值遗漏；全部候选另报有效率。历史搜索样本偏向原距离代理，只能做诊断，不能独立证明新搜索更优。

**阶段 B：保持完整评估外层，接入可替换评分与种子。** 比较交互距离、阶段/EZ 接入、兼容分组三种评分；先不改下游 router、终态和硬件。保留相同种子、相同完整编译预算及独立随机探索，观察排序变化带来的效果。

**阶段 C：加入短前瞻编译。** 对较少候选编译前 K 个服务阶段，记录预测终态后再评分后续；最终仍完整执行。前缀最好并不保证全程最好，必须保留长电路和换伙伴测试。

若阶段 B 主要问题仍是进入 EZ 失败，优先检查候选与下游运输模板不匹配的原因。不要为了提高有效率放宽物理限制，也不要将有限规划器失败标成硬件不可能。

## 10. 实验应该怎样证明改进

建议使用链/环、网格交互、重复同伴、频繁换伙伴、稀疏与密集混合电路，并覆盖不同原子数、空位率、SZ/EZ 形状和 AOD 行列容量。测量和条件控制作为单独覆盖组，避免代理只支持 CZ 却宣称全门集优化。

至少保留四组算法：用户基线、固定 seed 的随机多起点、当前交互距离反馈搜索、建议的运输感知反馈搜索。它们共享电路、平台、下游编译选项与终态合同；分别按相同完整评估次数和相近墙钟预算比较，避免更贵的代理靠额外计算获益却未披露。

| 指标 | 能回答什么 |
| --- | --- |
| 完成全部服务的物理总时间 | 初始化最终有没有改善执行 |
| 最后逻辑门时间、服务收尾时间 | 收益是否被收尾抵消 |
| 运输/装卸批次、CZ 脉冲数 | 优势来自哪里；是否改变并行组织 |
| 有效候选数及失败分类 | 候选与当前编译器是否匹配 |
| 候选生成、编译、重放、录制墙钟 | 优化代价是否可接受 |
| 多 seed 的胜/平/负比例及分布 | 收益是否依赖一次幸运搜索 |
| 代理排名与实际时间的关系 | 代价函数是否提供了有效信息 |

消融分别去掉阶段权重、EZ 接入、兼容分组、空位移动、多样性选择；参数在训练/验证电路上确定后冻结，再测未参与调参的电路。小问题可枚举映射形成“固定编译器下的初态参考”，报告其中超时或失败项，不把枚举自动称为物理最优证明。

当一个方案只缩短距离而没有缩短总时间，或者有效候选更少，应保留这个负结果。它常常比继续调退火温度更能暴露真实瓶颈。
