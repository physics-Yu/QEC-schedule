# CZ随机电路训练与电路同步回放

## 训练合同

配置为[configs/rl/cz.json](../configs/rl/cz.json)，独立入口：

```powershell
.venv-rl-stage-b/Scripts/python.exe -m neutral_atom_experiments.rl.cz_training --output artifacts/rl-cz/attempt2
.venv-rl-stage-b/Scripts/python.exe -m neutral_atom_experiments.rl.cz_audit artifacts/rl-cz/attempt2
C:/python312/python.exe -m http.server 8801 --bind 127.0.0.1 --directory artifacts
```

- 固定8条训练、4条验证、6条测试，生成seed1701/1707/1713。训练4/6原子，测试4/6/8原子，各测试尺寸两例。
- 每条线路是两轮`H层 → 随机完美匹配CZ层`。随机洗牌全部原子后两两配对，不按基线输赢或几何可并行性筛选；拒绝同一标号线路的重复。中间H层避免相同CZ直接两次抵消。
- 每条4/6/8原子电路含4/6/8个CZ，H仅承担准备和依赖。输入DAG仍按同一原子的门顺序约束，没有为了并行跳过依赖。
- 固定实例布局为两行SLM，横向10μm、两行间隔20μm，位于同一EZ；单AOD为一行、n/2列，初始关闭。所有策略共享同一初态与原始holder/轴/开关终态；不是完整QEC多区线路训练。
- 两个训练seed11/29，图网络hidden32，模仿15轮，再PPO12更新，每更新2个连续片段、上限4步。奖励`-实际完整物理时间/1000μs`，包含装载/移动/光脉冲/归还/卸载/终态清理，失败保留完整惩罚。
- 每6更新验证选模，允许保留update0；最终对未训练、模仿、最后PPO、验证所选PPO、局部成本、随机策略统一测试。两seed×6电路×6策略=72次执行；同6条线路的重复测试不是72个独立实例。
- 同一环境、布局、终态与候选预算。新的随机分布和既有1Q报告不可直接以均值比较改善。

## 网络实际上能选什么

沿用隔离的`RestoringCandidates`，网络选择已合法实现的候选：CZ批次、每对原子的静止/移动角色、上下左右2μm目标方向。路线由既有占据格/axis-hold几何规划实现，所有动作提交`NeutralAtomEnv`并由执行器推进。

仍只支持有限批量、同位移候选，以及每批CZ原子回原SLM的恢复服务；服务级串行、批内CZ可并行，尚无1Q与搬运的跨服务重叠。并未学习自由连续路径、跨批驻留、任意二维重排或测量。ready8/candidate24/route16/规划60秒限制显式保留，不把有限候选外的失败称为物理无解。生产greedy和环境硬约束不改。

## 输入电路和原子动画联动

新增`experiments/rl/circuit_replay.py`，由真实记录器payload与同一case生成完整单页：

- 所有Q编号、门ID、1Q门、CZ两个端点和连线；按输入依赖与连线避让绘图，明确不是实际物理时间轴。交错的独立CZ连接分列绘制，避免重叠成看似四体门；同批执行由真实脉冲同时高亮。
- 点击/键盘激活门，调用共用viewer的`setTime`到实际脉冲中点。
- 播放、暂停、逐事件、拖动或跳转后，按真实operation区间更新待执行、准备、正在打光、已完成状态；门完成后仍可能在归还，不能将逻辑完成冒充程序结束。
- 提供所示电路JSON，保存recording.json以核对脉冲、计划、原子统计；纯观察，不改实时状态。
- 阶段A/B、horizon、random的后续RL导出均接入此生成器；当前用户打开的旧random两份动画已用相同已存计划重新物理重放并补齐电路，没有改变旧执行结果。
- CZ正式交付对所有6条测试线路导出seed11的最后PPO、验证选中模型与局部基线（共18页），不只挑网络赢的线路展示。若验证仍选模仿模型，标题明确写出update0；最后PPO页独立展示真正经过PPO更新的权重，不混淆两者。

浏览器禁止重新导航file协议，开发机用loopback 8801服务验收；旧8798服务保持。跨机器可从项目根目录运行上述HTTP命令。

## 结果和验收

第一轮在seed11未训练模型的8原子测试`test-cz-random-005`触发`CANDIDATES_EXHAUSTED`：120个原始候选，前24个均需两行抓取，而硬件只有一行；96个候选未被尝试。这不是电路物理无解。保留`artifacts/rl-cz/attempt1/failure.json`、失败checkpoint和逐候选拒绝原因，中止第一轮以免继续比较错误候选器。

修复位于隔离的`learning/candidates.py`：在候选实现预算前检查必要的X/Y轴容量，保留原action ID，记录`capacity_pruned/capacity_rejected_ids`；`generated = capacity_pruned + attempted + not_attempted`。合法候选仍经过相同完整物理检查，候选/路线/时间预算不变。容量可行不保证路线可行，不宣称搜索完备。

第二轮从初始权重以相同随机电路、seed和超参数重跑。该测试清单参与过工程故障定位，因此不宣称是完全未触碰的研究测试集；未用测试回报训练或选模。

最终结果记录在`artifacts/rl-cz/attempt2/report.json`、`summary.json`、`acceptance.json`。44项Python回归通过（49.21秒），连线避让改动后3项CZ测试再次通过（24.96秒），160模块架构边界0违规。

18页均经独立计划重放及完整门效果核对；磁盘selected/last权重重新加载执行通过。真实浏览器分别验收4原子CZ测试页、8原子验证选中模型页和8原子最后PPO页：门点击跳转、双CZ同时高亮、准备状态、32×播放至终点与零控制台错误。代表8原子页在448.782μs同时高亮g0008/g0010，2555.764μs定位g0023，3700.775μs完成24/24；不是声称18页都做了逐项人工交互。
