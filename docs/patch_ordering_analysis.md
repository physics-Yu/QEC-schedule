# 二维批量贪心的失败与离线改进分析

本分析保留一个真实反例：只最小化“当前恢复服务时间 / 当前完成 CZ 数”的二维贪心，虽然每次都会尽量使用便宜批次，却可能提前消耗未来大批次的一部分，使全电路变慢。以下正式观察来自完整 194 门执行；后续算法数字来自离线模型，尚不能当作已通过物理验收的新成绩。

**版本说明**：14082.1 μs 固定指向初版即时贪心的已录制反例。当前生产策略后续已加入本地优先和同源行/列子组，新的真实执行必须另列。离线脚本内部固定初版“同位移最大组 + 单门”候选族，仅在 `_closed` 方法中显式扩展子组，防止随着生产 `candidate_groups` 更新而悄悄改写旧模型对照。脚本输出不替代新版本 Executor 或浏览器结果。

## 实际失败的量化

数据分别在 `artifacts/surface-2d/patch_symmetric/` 和 `artifacts/workbench-surface-2d/36ffa951498a4be9993269810ebcd4c8/`。

| 指标 | 对称基线 | 即时每门平均成本贪心 |
| --- | ---: | ---: |
| 完成物理门 | 194 | 194 |
| 完整时间 μs | 8978.2 | 14082.1 |
| AOD 忙时 μs | 8935.2 | 14025.1 |
| CZ pulse 数 | 24 | 37 |
| LOAD / OFFLOAD 各自次数 | 26 | 39 |
| AOD 路程 μm | 1864 | 3107 |
| 原子累计路程 μm | 10042 | 9794 |
| Raman 忙时 μs | 43 | 57 |

贪心慢了 **5103.9 μs，约 56.85%**。新增 13 次批服务带来 2600 μs 装卸、3.9 μs CZ 激光；多 1243 μm AOD 路程带来 2486 μs 运动；Raman 多 14 μs，总和正好是 5103.9 μs。原子累计路程反而减少，因此单看这个指标不能判定调度改善。

基线把最后 27 个跨空间分量 CZ 分成 9 门和 18 门两批。即时贪心提前执行已 READY 的小片段，将这两个大组分别拆成 7 批，总计 14 批。新增 13 批中的 12 批来自这里；本地 32 个 CZ 仅从 22 批增至 23 批。这说明主要问题是提前消耗尚未完整就绪的同构跨分量门组。

第二个问题是候选不完整：同位移的三个 READY 门可能因 Cartesian 行列交点产生第四个意外捕获而整体非法；其中同一来源行或列的两门子集却可能合法。只尝试最大同位移组，失败后直接尝试单门，会漏掉这种可实现的双门联合捕获。

## 通用改进顺序

算法不读取 SGHZ 编号、逻辑 patch 标签或生成器专用信息：

1. 从当前固定占据点的最小非零中心间距构建等距最近邻图，取连通分量。本输入自动得到四个空间分量。跨较大空隙的点不会直接相连。
2. 只要存在两操作数位于同一分量的 READY CZ，先在这些本地 READY 门中选批；没有本地 READY CZ 时允许跨分量门推进。如果本地候选全部物理失败且还剩构造预算，也会尝试跨分量 READY 门，避免把“本地优先”误当成硬性执行权限。
3. 每个同位移最大候选组之外，加入按移动操作数来源 x 相同、y 相同划分的子组，并保留单门回退。候选按稳定键去重，不枚举指数个子集。
4. 廉价检查实际行列开启后的捕获闭包、终点实际作用对、全阵列边界。通过者再做真实路径、完整 backend/audit；廉价检查不能替代后者。
5. 在这个候选集合中继续使用真实恢复服务成本 / 批大小评分。跨分量大批因为本地准备先完成而较容易保持完整。

该 locality 规则是空间启发式，不是普适最优法：任意编辑电路可能不存在这样的组件结构，组件内也可能本来就需要尽早跨组件传递依赖。因此必须保留失败原因与相同输入对照。

另一个可比较的同步启发式是：在本地 READY 集合里，统计每个组件已完成的本地 CZ 数，仅优先该计数最小的组件，再应用上述合法子组和成本评分。它推动落后组件追上同构阶段；但不同组件电路结构或长度不同时，完成门数不代表相同进度，不应把这个规则称作一般关键路径最优策略。

## 离线模型结果

`examples/analyze_patch_ordering.py` 保留完整 CZ 偏序，收缩单比特门为零时间；精确检查 Cartesian 捕获闭包、终点所有作用对，调用相同有界半格无障碍图计算运动距离。它不执行实际载原子扫掠、支撑切换和 Raman 时间安排，不生成可执行计划。

| 策略 | CZ 批数 | CZ 服务与终态空载估计 μs |
| --- | ---: | ---: |
| 对称基线 | 24 | 8175.2 |
| 即时平均成本贪心 | 37 | 13265.1 |
| 仅本地优先 | 25 | 8257.5 |
| 逆向剩余 CZ 深度优先 | 27 | 9342.1 |
| 本地优先 + 同源行/列闭合子组 | 24 | 7345.2 |
| 本地进度同步 + 同源行/列闭合子组 | 21 | 7088.3 |

基线和即时贪心的模型结果各加两次固定联合运输 760 μs，分别精确等于实际 AOD 忙时 8935.2 和 14025.1。这个核对增加了模型对本输入的解释力，但不证明新候选一定通过所有路径或时序检查。

单独本地优先虽然恢复最后 9/18 门大批，仍比基线模型多 82.3 μs；关键路径排序也没有改善。加入闭合子组后才出现明确模型收益：分别比基线少 830 或 1086.9 μs。这里不把更深前瞻、更多规则或更大批的名字当成性能证明，下一步必须真实编译验证。

完整次序、批大小、方向、估计时间保存在 `artifacts/surface-2d/ordering-analysis.json`。复现：

`python examples/analyze_patch_ordering.py artifacts/surface-2d/patch_symmetric/input.json --output artifacts/surface-2d/ordering-analysis.json`

本次分析没有修改 `src/`；生产算法与正式物理/浏览器结果由主任务单独实现和记录。

后续失败分支补丁增加上述跨分量回退：只有本地候选流已穷尽、尚无成功计划、共享构造预算仍有剩余时触发。原成功路径的候选顺序、评分和计划保持不变；回退会记录 `fallback_to_cross_component`，全部失败时仍保留本地与跨分量各自的原因。`tests/test_patch_local_fallback.py` 四项故障注入验证剩余预算、失败隔离以及原本地成功优先，均通过；正式完整大运行与补丁后的独立重放由主交付分别记录。
