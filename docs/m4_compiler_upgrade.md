# M4 编译器升级：最短路径与搜索成本

2026-09-11。对应用户的 7 原子、单台 1×2 AOD、12 门输入 `f902f3305086474a89146d091f9c5035`。这次 90 秒失败不是最后一个 AOD trap 无法执行：在相同的 11/12 进度下，剩余 G009 CZ(Q000,Q006) 已有 8 个合法候选，超时发生在比较它们的前瞻推演期间。

## 已完成的升级

原路径层只枚举有限的折线模板。现在 M4 使用 **A* 半格通道图最短路**：固定当前 holder、trap 开关与目标，用 `2.5+5k μm` 的横竖通道和短端点接入构图，每条边检查整个刚性阵列的真实扫掠。活动空 trap、附带原子、SLM 障碍和装卸边界都参与检查。起终点相同不意味着不同装载或开关状态可以共享避碰结论。

A* 的已走距离加 Manhattan 剩余距离下界决定搜索顺序。先求同图忽略障碍的最短路线，实际避碰审核通过就已经达到下界；不通过才进一步绕障搜索。已通过一个旧折线模板全部失败的双墙夹具，并由独立 Dijkstra 确认最短距离为 80 μm。算法原理来自 [Hart、Nilsson、Raphael 的 A* 原论文](https://ai.stanford.edu/~nilsson/OnlinePubs-Nils/PublishedPapers/astar.pdf)；本项目的图定义、证明前提和实现见 [A* 合同](astar_routes.md)。

性能瓶颈主要是另一层：原前瞻只展开 32 个分支，却触发约 11.1 万次操作重演，每个事件都会从头重建已验证的操作历史。现改成复用独立重建的期望前缀，每次仍对照当前状态、trace 顺序、DAG 和待执行事件；只保留 32 个计划/环境的最近前缀。内部推演用持久状态分支，外部 checkpoint 恢复保留完整审计。精确 trace 字符串只读解析也有有界缓存。

同一输入升级后重演约 1.6 万次，运行态验证调用反而由 3320 次增加到 4276 次（因为显式保留了更多交接停点）；减少的是重复计算，没有通过减少校验次数获得性能数字。热缓存位置/光阱/事件/指标/硬件篡改和私有分支隔离测试均保留。

## 当前贪心究竟做什么

1. 从 DAG 得到 READY 门，按配置的有限门/站点预算尝试候选。对 CZ 比较伙伴选择、EZ 站点、四个相对方向及明确的 trap 开关/装卸安排。
2. 每个候选内部由路径规划器找固定配置下的图最短运输路线，再用完整物理校验得到服务时间。
3. 贪心按当前候选服务时间、装卸次数、移动距离、确定性键依次排序。它不预测全电路代价。之后把依赖、资源与几何均允许的同类型单比特门尽早放入安全时间窗口。
4. 前瞻额外比较有限 KEEP/RETURN 分支，按真实推演时长、终态清理成本和剩余脉冲关键路径下界评分。该总分是有限视野估计，不是全电路成本下界或全局最优证明。

## 尚未解决的边界

最短性仅覆盖固定状态、固定 masks、固定目标的有限 rigid 通道图；开关方案、装卸、目标站点和门顺序仍是有限候选调度。尚无全局最大并行、任意 32 原子/64 门成功率或实时编译延迟保证，M5 批量 CZ 不在本次升级中。

进一步性能分析仍看到重复 AOD 配置构造、候选公共前缀和归还试算成本。后续优先针对这些纯计算建立完整键的缓存/复用，再评估按实际主机时间分配的搜索预算与可见的降级策略；不能默默换成贪心或把预算耗尽报告成物理无解。更复杂的增量寻路只在重复相近几何请求的收益有证据时引入，详见 [算法调研](m4_pathfinding_research.md)。
