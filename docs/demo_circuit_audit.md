# Demo电路审计与横向CNOT定位

2026-09-14。核验对象为当前`configs/studio/demos/*.json`全部五份demo。用户随后明确无需新增可读显示，本轮不改前端、不改物理模型、不改保存的门列表。

## 两逻辑CNOT在哪里

两逻辑单轮与多轮QEC demo都在**显示第39列**对目标块Q009–Q017执行9个H，在**第40列**包含9个CZ：

`Q000→Q009, Q001→Q010, Q002→Q011, Q003→Q012, Q004→Q013, Q005→Q014, Q006→Q015, Q007→Q016, Q008→Q017`。

第40列的原生门ID为QEC0302–QEC0310。截图最右侧第40列CZ就是这部分；目标H在下方第二个data块，所以截图上半块看不到。界面“跳到列”输入39可定位。

未优化逻辑块是H(target)→CZ→H(target)，共27个原生门。原第41列的9个末尾H与后续稳定子提取中同一数据线遇到的第一个H相消，所以本阶段保留18个门。不能截取这18个门、脱离后续阶段，单独称其为完整CNOT；完整线路等价性由HH消去证明及优化前后量子运行对照核验。

例：Q009上的QEC0311与QEC0332相消。九组具体ID见生成报告的cross_stage_hh字段。消去仅涉及同一wire上相邻的无条件H（忽略其他wire上的操作），不消去测量或条件Pauli。

同向CSS surface-code块的对应数据CNOT实现横向逻辑CNOT，可对照[Bluvstein等原文的Surface code and its implementation](https://www.nature.com/articles/s41586-023-06927-3)。本文只核对该门结构，不把当前项目的模拟范围等同于论文全部实验能力。

## 截图中的连续X/Z是什么

`surface_qec._corrections`将syndrome查表展开为带condition的X/Z。比如Q000上的QEC0211要求prepare_X0四位为1000，QEC0212要求1001；两者不可能同时成立。相邻XX/ZZ不能按无条件门抵消。

当前界面网格未直接标出这些条件，点选门后详情才显示AND条件，确实容易误读；按用户最新要求，本轮保留显示不改。所有同阶段/同原子/同Pauli的替代分支均做了两两条件互斥检查。

单轮两逻辑demo共184个条件槽；本轮理想电路seed0实际执行3个条件Pauli、跳过181个，seed7执行2个、seed29执行4个。条件为假不施加量子门；物理运行仍按既有合同保留控制槽时间。这种静态查表展开有表示与控制时隙开销，不是已经优化为动态decoder指令或Pauli frame。

- 文件门列表按实际column/id排序，与重新生成的电路逐字段一致；空默认字段规范化后比较，配置文件排序不等于门生成顺序。

- 四逻辑酉编码demo的32个码稳定子及4个逻辑GHZ稳定子独立验证通过；四H demo直接验证4条独立线路的同列H定义。

复现：`python tools/audit_demo_circuits.py --output artifacts/demo-circuit-audit-2026-09-14/report.json`。脚本位于tools外部审计层，不参与环境或编译决策。报告包含门计数、具体原子对、显示列号、HH消去ID及各seed条件门计数。

范围：这是全部内置demo的电路定义/量子语义审计，没有重跑运输规划、完整物理动画或全部噪声域穷举；不证明任意噪声下容错，也不承诺规划器把逻辑可并行的9对全部安排在同一个物理pulse。
