## 1. 研究边界与输入输出

研究从给定的 PhysicalCircuit 出发，不负责逻辑编码、纠错码生成或映射到物理比特。输入包括门及参数、Q 身份、平台能力与成本、初始 placement/光阱状态，以及明确的程序终止条件。默认所有原子初始化于 SZ 的已开启 SLM 格点。

输出是可独立校验、确定性执行和回放的**带依赖与时间的原子操作程序**：移动、光阱开关、SLM↔AOD 交接、门脉冲和必要等待/清理。研究的是这些操作的选择、组合、资源约束和完成时间；不要求生成激光场、RF/AWG 波形、运动量子态或保真度。

M4 工作台新增显式 adaptive EZ 候选网格，初始关闭；compiler 按操作数和占位排序全网格并精确验证有限候选，执行真实开关与换伙伴。旧双站点输入保持原几何。候选坐标属于不可变 world，实际光阱状态属于动态 masks；新网格不继承旧 M3 平台族可路由证明。输入预算、失败阶段、候选尝试/遗漏与实际执行片段必须可导出复测，见 [M4 规范](../docs/milestone4_greedy.md)。

门集为 CZ 加通用单比特 U(theta,phi,lambda)，别名和参数约定见 [state_circuit](state_circuit.md)。这是可声明支持的电路族，不包括尚无结果/反馈语义的测量、reset 或条件分支。“任意 physical circuit”必须限定在支持的门集和已验证的平台布局族内。

## 2. 职责与数据流

```text
PhysicalCircuit + platform + initial state + terminal condition
  -> 门参数归一化 / 逻辑 DAG
  -> Scheduler：候选任务目标、约束和可用时间窗口
  -> Compiler：局部合法操作图、资源区间、成本与预计终态
  -> Scheduler：选择候选、安排开始时间与可重叠操作
  -> 独立 validator：逻辑、物理、时序及终止条件
  -> Executor：唯一状态提交者，事件推进统一时钟
  -> trace / metrics / 可复用原子动画与 schedule
```

这里 scheduler 是 planning/policy 与调度运行层共同承担的职责；它负责全局次序、驻留、预取、归还和允许的 lookahead。compiler 在给定起态、目标域和约束下选择可实现的交接与路线。硬件 backend 定义动作是否合法及成本，不能暗中选择未来电路策略。Executor 执行已排定的时间和验证边界，不替 scheduler 优化顺序。

同一任务可以有一个或少量有界候选；不同终态、资源占用或通道的候选可能对未来不同，不能只保留距离最短者而声称全局最优。文献中的 compiler 常包括调度；这里的命名是项目内部分工，参见 [研究索引 R5/R10](research.md)。

## 3. 任务、操作与门不是一一对应

一个任务表达目标状态或效果，可没有 gate，例如将 b 停到某个 EZ SLM 空位、保留 loaded 原子但换位置、仅归还、关闭空 AOD 后重新定位。任务也可要求执行一个门并保持一个允许的终态。当前 basic 仍可把完整 CZ 往返打包成一个候选。

“一个门分成几个计划”指拆开 **准备 → pulse → 后处理**，不是把 CZ 脉冲拆成几个不完整的量子门。准备完成只改变物理状态；CZ 完成只提交该门的逻辑效果；归还不重复完成门。一个原子的预先运输也可以服务后续多个门，不能强制归属于唯一 gate。

操作图需要稳定 task_id/op_id、依赖、受影响原子/光阱、持续时间、资源需求、状态前置/后置条件；gate_id 只在相应逻辑效果和关联元数据中出现。零 pulse 的任务必须合法；同一 gate 的效果必须恰好完成一次。M5 才扩展同时多个 CZ 的实际作用集。

## 4. 目标请求与编译结果

以下是语义字段，具体类型名在实现时确定，不把它们当作已存在的 API。

| 请求内容 | 必须表达的语义 |
| --- | --- |
| 起始状态 | 已提交快照，以及必要的在途轨迹、占用和预约；持久 EZ/loaded 状态均可成为起点 |
| 目标 | gate 效果、指定 holder、位置/区域约束或允许的终态集合；明确哪些部分由 compiler 分配 |
| 限制 | 可使用原子、SLM 站点、AOD 行列、时间窗口、允许附带运输集和 backend 能力 |
| 搜索预算 | 有限目标/路线候选数、时间或节点数，确定性次序；进入诊断和复现信息 |

| 编译结果 | 必须表达的语义 |
| --- | --- |
| 合法候选 | 操作依赖图、相对时间/可调窗口、资源区间、真实时长与路程、预计终态及 gate 效果 |
| 适用条件 | 状态版本/相关状态指纹、几何和能力版本、资源与终态假设；调度平移时间后仍需验证 |
| 拒绝原因 | 不支持能力、几何违规、资源受限、终态不可分配、预算耗尽等；包括失败位置和尝试范围 |

局部 compiler 可优化固定任务的距离/时间；是否值得多一次装卸换取以后复用由 scheduler 判断。装卸次数只在给定起终态与协议后可能固定，不能当成所有策略共有常数。也不允许用零成本隐含准备满足前置条件。

## 5. 单一时钟与三个可观察完成条件

只有一个仿真时钟。下列是同一时间轴上的不同事件，不是三个阶段屏障：

1. **逻辑门完成**：pulse 或 1Q 操作结束，释放逻辑后继。
2. **具体资源释放**：某个原子结束交接、某条 AOD 轴或 Raman 通道空闲；不同资源可在不同时间释放。
3. **程序完成**：全部要求的门完成，并满足输入声明的终止 placement/光阱/清理条件，且没有必须完成的在途操作。

plan 完成只是软件分组边界。一个原子可在 CZ 后继续由 EZ SLM 保持，另一个原子在归还；后继是否可执行取决于自己的依赖、holder 和资源，不取决于前一个完整往返 plan 的结束。

下面只解释调度语义，时间为示意值，不是硬件预设。t=100 时 CZ(a,b) 刚结束，a 已由 SLM 持有，b 仍由 AOD 持有；Raman 与运输资源独立，路径已验证。

| 统一时间 μs | 单比特资源 | AOD/交接资源 | 可用性变化 |
| --- | --- | --- | --- |
| 100–105 | H(a) | b 返回、卸载的一部分 | a 静态稳定，可先做后继 H |
| 105–160 | 空闲 | 继续 b 返回、卸载 | t=160 b 才满足 SLM 1Q 前提 |
| 160–165 | H(b) | 接回并归还 a 的一部分 | b 的 1Q 与 a 的运输可重叠 |
| 165–230 | 空闲 | 完成 a 归还/卸载 | t=165 逻辑完成；t=230 满足归还终止条件 |

资源预约按操作及其必要持续占用区间，使用半开区间 [start,end)。光阱承载和站点占位在两操作间仍然持续，不能因没有当前操作而自动释放。安全检查覆盖整个时间区间的真实轨迹/影响范围，不只比较资源 ID。相同时间先完成并提交、再检查可开始操作；同时事件冲突需一致的批次校验与确定性顺序，不能靠碰巧的插入顺序掩盖冲突。

legacy 的单操作 active_plan、全计划预约和“唯一下一事件”恢复规则仅用于串行；schema 13 新增 scheduled program envelope、多个 running_operations、操作级预约和完整事件时间表，保留起态指纹并独立重建并发前缀与未来操作。快照保存全部在途操作、轨迹、预约与门效果，并能够继续运行。

## 6. 优化目标与统计

主目标是从统一 episode 起点到**程序完成**的总耗时，包含必要准备、开关/交接、运输、等待与尾部清理。逻辑完成时间作为辅助指标。若允许最终留在 EZ/loaded，必须在输入中声明，不能与要求全部归还的策略直接比较总时间。

各资源 busy time 取占用区间并集；跨资源类别的时间可以重叠，合计不必等于 wall time，百分比不能伪装成互斥分解。并行利用率需要说明资源容量及分母。schedule 保留真实先后/重叠关系，默认按少量资源或动作类别聚合，选中门/原子后展开详情。

## 7. 失败与完成保证

搜索期间拒绝一个候选是正常结果，可继续检查预算内其他候选。最终无候选、资源死锁或选中计划未通过精确验证时，终止本次运行并给出可见结构化错误；保留输入、当前状态、未完成 DAG、冲突操作/资源、尝试范围、trace/checkpoint。不得静默跳门、部分提交、无限等待或把 stalled 当成功。

“自由度足够总能完成”需要额外前提：支持的门集、可用的 EZ 停车位、合法交接、足够安全通道和可恢复的空阱配置。先定义并验证一个可支持布局族，给出“串行完成一门并恢复可复用状态”的构造基线，再通过归纳支持该族内任意有限电路。单比特操作也必须在相应位置可用。有限搜索失败只证明这次没有找到方案，不证明所有物理规划无解；R9 的构造性论证也不能直接证明任意有限分区布局都可行。
