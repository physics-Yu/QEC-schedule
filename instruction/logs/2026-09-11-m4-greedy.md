# M4 贪心编译与可编辑验收

状态：2026-09-11，本轮实现与机器验收完成；真实浏览器验收受工具限制未完成。M4 的 critical-path / 有限 lookahead 尚未实现，不把 greedy 首版等同整个 M4 完成。

## 用户要求与范围

用户授权实现此前讨论的 M4 贪心，并明确要沿用可编辑线路 → 编译 → 实际回放工作台。保留初始条件优先、固定单比特光 1 μs、最高 32×、随机载入、撤销/重做和输入/回放导出。

使用单 AOD、单 Raman 的原物理能力、共享 validator/Executor。新增有限 anchor/EZ 候选成本选择、实际路径时间排序、连续 Raman 填窗和持久位置复用。采用滚动非抢占 AOD 服务段，段内 Raman 按完成事件补充；不是任意事件重做全局优化，不支持批量 CZ、多 AOD、测量反馈或 RL。

## 实现入口

- motion/greedy.py：GreedyCompiler、GateCandidate、ShortestCorridorPlanner；双向静态伙伴/有限 EZ 分配，显式占位迁移，完整装卸/开关/运动/pulse 成本。纯预测，不写实时状态。
- simulation/m4.py：run_m4、fill_raman；连续 MOVE 窗口每 1 μs 完成后重算 READY，同一原子的后继可连续填入。消除 M3「有 READY Raman 就优先归还 loaded」策略；提交前仍完整审计 scheduled program。
- visualization/workbench.py / workbench.js / workbench.html / workbench_server.py：compiler=greedy、新默认 8 门示例、可展开决策表、decision_log / decisions.json。旧无 compiler 输入保留 legacy。
- examples/run_m4.py：真实执行录制、候选/预算/诊断/终态产物；重跑前撤销旧 verification。examples/render_m4_acceptance.py：从真实数据生成验收 PNG 与对照 JSON。
- configs/workbench/m4_parallel.json；tests/test_m4.py、tests/m4_controls.cjs、tests/m4_workbench_controls.cjs。

## M4 触发的 M3 退出修正

32 原子、两个 EZ 均驻留时，门全部完成但返回 NO_TERMINAL_CAPACITY。原因是 PersistentTargetCompiler.target 将所有最终目标点排除在临时停车之外，空闲的 SZ 目标也不可用。失败保留在 artifacts/m4-scale-32。

修复为允许空闲的后续目标点临时停车；已完成归位的目标被占用，不会被 spare 选择，后续目标继续逐个修复。所有停车仍包含显式装卸/路线与共享校验，未放宽物理参数或增加容量。四原子最小反例与旧置换测试先通过，再重跑 32 原子及完整回归。

首次完整回归因发现此真实问题主动中止，其进度不计最终 PASS。编辑器测试首次只因导入规范化排序与原数组顺序不同而断言失败，改为按 gate ID 比较同一输入内容；实际编辑器未修改该既有规范化语义。
